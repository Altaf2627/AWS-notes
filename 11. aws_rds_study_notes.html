AWS RDS (Relational Database Service)

1. What is AWS RDS?

Amazon RDS (Relational Database Service) is a managed relational database service provided by AWS.

It allows you to create, operate, scale, monitor, back up, and maintain relational databases without managing the underlying database infrastructure manually.

Relational Data

Relational data is generally organized into: Tables, Rows, Columns.

Example:

IDNameEmail
1Rajuraju@email.com
2Shamsham@email.com

Popular relational database systems include:

MySQL PostgreSQL Oracle Microsoft SQL Server MariaDB

AWS RDS supports several popular relational database engines.

2. Why Use RDS?

Normally, if you install MySQL yourself on a server, you are responsible for many administrative tasks. With RDS, AWS manages much of the underlying database infrastructure.

Important RDS Benefits

  • Automated maintenance
  • Monitoring & Backups
  • Scaling options
  • High Availability & Fault tolerance
  • Read replicas & Recovery options
  • Security controls
  • Easier database administration

Simple Example

Without RDS:

EC2→Install MySQL→Configure MySQL→Patch→Monitor→Backup→Maintain

With RDS:

Application→RDS

AWS handles many of the infrastructure-management tasks for you.

Key Concept RDS is a managed database service, not simply a database installed manually on an EC2 instance.

5. Creating an RDS Database

Go to the AWS Console and search for: RDS → Relational Database Service
Then: Databases → Create database

AWS provides different creation approaches.

Easy Create

Designed to make database creation simpler and faster. AWS automatically chooses many configuration options based on the selected use case.

Typical choices include:

  • Production
  • Test
  • Free Tier

Standard Create

Gives you much greater control over database configuration.

For learning and practical purposes, Standard Create is useful because you can understand individual configuration options.

6. Selecting the Database Engine

For the practical, MySQL is selected. RDS supports multiple database engines, such as:

MySQL PostgreSQL MariaDB Oracle Microsoft SQL Server

The database engine should be selected according to the application's requirements.

7. Templates

RDS provides templates based on the intended workload. Typical options include:

  • Free Tier: Useful for learning, practice, testing, small experiments.
  • Production: Designed for production workloads where requirements such as High Availability, Performance, Reliability, Fault tolerance are more important.
  • Test/Development: Useful for development and testing environments.

8. High Availability in RDS

For production environments, RDS can be configured across multiple Availability Zones (AZs).

AWS Region | ----------------------- | | | AZ-1 AZ-2 AZ-3 | | | DB-1 DB-2 DB-3

The exact architecture depends on the selected RDS configuration.

Important Point High Availability helps protect the application from failures affecting a single Availability Zone.

9. RDS Instance vs RDS Cluster

The transcript distinguishes between database instances and clusters.

Instance-based setup

A primary database instance handles database operations while another instance can remain available for failover depending on the configuration.

Primary DB ↓ Replication ↓ Standby DB

If primary fails, AWS performs failover.

Cluster-based setup

A cluster can provide multiple database instances with capabilities designed for higher availability and/or read scalability, depending on the selected RDS database technology.

10. Storage & Auto Scaling

RDS provides storage options such as SSD-based storage. Storage configuration can include: Allocated storage, Storage type, Storage scaling, Performance-related settings.

Storage Auto Scaling

Storage Auto Scaling can automatically increase allocated database storage when the database approaches its storage capacity.

Capacity Limit→Usage Increases→Threshold Reached→Storage Automatically Increases

This helps reduce the risk of the database running out of storage.

11. Database Credentials

When creating an RDS database, you configure credentials for accessing the database. Common credentials include Master username and Master password.

Username: admin
Password: ********

Security Reminder

  • Do not use simple passwords.
  • Do not expose database credentials publicly.
  • Do not hard-code passwords into application source code.
  • Use secure secret-management practices.

12. Connectivity

One important RDS configuration is deciding how the database will be accessed. The database may need to communicate with: EC2, Application servers, Other AWS resources, External systems (depending on the architecture).

The networking configuration includes: VPC, Subnets, Security Groups, Public/private accessibility.

13. Public Access

The practical demonstrates a database configured for public access so that it can be accessed during testing. However:

Publicly accessible databases are generally not recommended for production unless there is a specific security requirement and the network access is tightly controlled.

A better production architecture is usually:

Internet→Load Balancer→Application / EC2→Private RDS

The database should generally be protected from direct public Internet access.

14. RDS Security Groups

A Security Group acts as a virtual firewall controlling network traffic to the RDS instance. For MySQL, the standard port is: TCP 3306.

Source → Allowed
Port → 3306
Protocol → TCP

Practical Setup vs Production

The transcript opens MySQL port 3306 to a broad source for testing. However, this is not recommended for production. A more secure approach is:

EC2 Security Group
→ TCP 3306 →
RDS Security Group

This allows the database to accept connections specifically from the application server rather than from the entire Internet.

19. Connecting Node.js to RDS  |  20. Env Variables

The Node.js application needs database connection information. The RDS endpoint acts as the database host. The practical uses environment variables to provide this info.

DB_HOST = RDS Endpoint DB_USER = admin DB_PASSWORD = ******** DB_NAME = myapp DB_PORT = 3306

Why Env Variables?

They help separate configuration from application code. Instead of writing credentials directly into source code (password = "..."), the application can read them from its environment. For production, use secure secret-management.

RDS Operations (25 - 28)

25. Monitoring: RDS provides monitoring capabilities. Important metrics include: CPU utilization, Database connections, Storage usage, Database activity, Performance-related metrics.

26. Current Activity: The RDS dashboard can show information about active database connections (e.g. Connection 1 → App, Connection 2 → Terminal). This helps identify how many clients are connected.

29 - 32. Automated Backups & Snapshots

29. Automated Backups: Supports data recovery, point-in-time recovery, protection against accidental changes, and disaster recovery. Retention depends on config.

30. RDS Snapshots

A DB snapshot is a point-in-time backup of an RDS database. It can later be used to restore a database.

RDS Database↓Snapshot↓Stored State

31. Restoring & 32. Manual

If database is deleted, but snapshot exists:

Snapshot→Restore→New DB

Manual Snapshot: Useful to preserve a specific state before major changes, testing, migration, or risky config changes.

33. Snapshot Copy Across Regions  |  34. Sharing

Mumbai Region→Snapshot→Copy→Another Region

This supports: Disaster recovery, regional migration, business continuity, geographic redundancy. RDS snapshots can also be shared with other AWS accounts for cross-account migration and collaboration.

35. Multi-AZ Deployment  |  36. Read Replicas

35. Multi-AZ: Primarily designed for High Availability and failover.

RDS | ---------------- | | Primary Standby AZ-1 AZ-2 | | Sync replication ↓

If primary fails, AWS performs failover. Multi-AZ is for HA, not read scaling.

36. Read Replica: Designed to improve read scalability.

Primary / \ ↓ ↓ Read Replica Read Replica

Primary handles writes, replicas handle reads. Reduces read workload on the primary database.

37. Multi-Region Read Replica  |  38. Multi-AZ vs Read Replica

A primary instance exists in one Region and a read replica exists in another. Benefits: lower latency for closer users, geographic distribution, DR strategies.

39. RDS Cluster  |  40. Aurora  |  41. Arch Comparison

39. Cluster Architecture: Multiple instances participate in a cluster (Primary = Read/Write, DB-2/DB-3 = Read).

40. Amazon Aurora: Cloud-optimized DB engine compatible with MySQL/PostgreSQL. Designed for high performance, high availability, scalability, automated management, failover.

41. Quick Comparison

  • Basic: App → RDS
  • Multi-AZ: App → Primary → Standby (HA)
  • Read Replica: App → Primary + RR1/RR2 (Read scale)
  • Multi-Region RR: Region A Primary → Region B Replica (DR/Geo read)

47. Important Interview Questions

Q1. What is Amazon RDS?
Amazon RDS is a managed AWS service for running relational databases.
Q2. Why use RDS instead of installing MySQL manually on EC2?
RDS reduces database administration work by providing managed capabilities such as backups, monitoring, maintenance, scaling options, and high-availability features.
Q3. Which databases can be used with RDS?
MySQL, PostgreSQL, MariaDB, Oracle, Microsoft SQL Server.
Q4. What is the default MySQL port?
3306
Q5. What is a DB snapshot?
A point-in-time saved state of an RDS database that can be used for restoration.
Q6. What is Multi-AZ?
A configuration designed primarily for high availability and failover.
Q7. What is a Read Replica?
A replicated database instance designed primarily to handle read workloads.
Q8. Multi-AZ vs Read Replica?
Multi-AZ → High Availability
Read Replica → Read Scalability
Q9. What is the RDS endpoint?
It is the network endpoint used by an application/client to connect to the RDS database.
Q10. What is Aurora?
Aurora is an AWS cloud-optimized relational database engine compatible with MySQL and PostgreSQL technologies.
