AWS Route 53 — Detailed English Notes

1. What is Amazon Route 53?

Amazon Route 53 is AWS's scalable DNS (Domain Name System) web service.

Its main purpose is to translate a domain name into the destination required to reach your application.

Simple example

Instead of accessing your website using: http://54.123.45.67

You can use: http://www.example.com

The user enters the domain name, and DNS helps direct the request to the appropriate server or AWS resource.

⭐ Key Point

Route 53 is mainly used for DNS, domain registration, health checks, and traffic routing.

2. What is DNS?

DNS = Domain Name System

DNS translates human-readable domain names into IP addresses or other DNS destinations.

Without DNS

Browser ↓ IP Address (54.x.x.x) ↓ EC2 Server

The user needs to remember the IP address.

With DNS

Browser ↓ example.com ↓ DNS ↓ IP / AWS Resource

This makes accessing applications much easier.

3. Why is it called Route 53?

The number 53 refers to the standard DNS port: DNS → Port 53

Hence: Route + 53 = Route 53

🧠 Remember DNS commonly uses port 53.

4. Basic Route 53 Architecture

A simple Route 53 setup can look like this:

User │ ▼ Browser │ ▼ example.com │ ▼ Route 53 DNS │ ▼ IP Address / AWS Resource │ ▼ EC2 / S3 / ALB / Other Endpoint

Route 53 determines where the DNS request should resolve based on the records and routing policies you configure.

6. Domain Name Registration

Before using a custom domain, you need to have a domain. There are two common approaches:

Option 1 — Register through AWS

You can register a domain using Route 53.

AWS Route 53 ↓ Register Domain ↓ example.com

Domain registration generally involves a fee, usually based on the domain extension and registration period.

Option 2 — Register somewhere else

You can purchase/register the domain from another registrar, such as a third-party domain provider. Then you can configure that domain to use Route 53 for DNS management.

⭐ Important Domain registration and DNS hosting are related but separate concepts.

7. Hosted Zone

A Hosted Zone is a container in Route 53 that stores DNS records for a domain.

example.com │ └── Hosted Zone │ ├── A Record ├── AAAA Record ├── CNAME Record └── Other Records

You can think of a hosted zone as: The DNS configuration area for your domain.

8 & 9. Hosted Zone for External Domains & Name Servers

Suppose your domain is registered with another provider.

Domain Registrar→example.com

You create a hosted zone in Route 53. Route 53 provides name servers for the hosted zone. You then configure the domain registrar to use those Route 53 name servers.

Domain Registrar │ ▼ Route 53 Name Servers │ ▼ Hosted Zone │ ▼ DNS Records

DNS propagation

After changing name-server information, the change may not become visible everywhere immediately. Propagation/caching can take time.

⚠️ Note The exact time is not guaranteed to be exactly 24 hours. It depends on DNS caching and TTLs.

10. DNS Records

A DNS record tells Route 53 how to handle a particular name.

www.example.com→Record→IP / AWS endpoint

Common record types include: A, AAAA, CNAME, MX, TXT, NS, and Alias records.

11. A Record

An A record maps a domain name to an IPv4 address.

Name: www
Type: A
Value: 54.123.45.67
www.example.com→54.123.45.67

12. AAAA Record

An AAAA record maps a domain name to an IPv6 address.

Domain→IPv6 Address

13. CNAME Record

A CNAME (Canonical Name) record maps one domain name to another domain name.

www.example.com→app.example.com

14. Alias Records

Route 53 supports Alias records for supported AWS resources (like S3 websites, ALB, CloudFront). Instead of an IP, you point to the AWS resource directly.

example.com→AWS Resource
⭐ Quick Summary
  • A record: Domain → IPv4
  • AAAA record: Domain → IPv6
  • CNAME: Domain → Domain
  • Alias: Domain → Supported AWS Resource

15. Simple Routing Policy

The simplest routing policy is Simple Routing.

User ↓ example.com ↓ Route 53 ↓ One destination (e.g. EC2 Instance)

This is suitable when you have a simple setup with one primary destination.

16. Why Routing Policies Are Important

Suppose you have multiple servers: Server 1 → Europe and Server 2 → Mumbai.

You may want Route 53 to decide:

  • Which server should receive the request?
  • Which region is closest?
  • Which server is healthy?
  • How much traffic should each server receive?
  • What should happen if one server fails?

Route 53 provides different routing policies for these requirements.

17 & 18. Latency-Based Routing

Goal: Send users to the AWS region that provides the lowest network latency among your configured destinations.

Route 53 / \ / \ Europe Mumbai EC2 EC2

Concept

European User → Route 53 → Europe EC2

Indian User → Route 53 → Mumbai EC2

This can improve user experience when the regional endpoint is healthy and offers lower latency.

⭐ Important Latency-based routing is based on measured network latency, not simply "nearest on the map."

19. Weighted Routing

It allows you to distribute traffic according to assigned weights.

Route 53 / \ 50% 50% / \ Mumbai Delhi

This can be useful for: Traffic distribution, Testing, Gradual deployments, Blue/green deployment strategies.

⚠️ Note Weighted routing does not mean that every small batch of requests will be split with mathematically exact percentages. It represents the intended distribution over time.

20. Failover Routing

Failover Routing is used when you have a primary and backup destination.

Primary Server │ ▼ Health Check │ ├── Healthy → Continue using Primary │ └── Unhealthy ↓ Backup Server

Example:

Primary: Europe EC2 | Secondary: Mumbai EC2

User→Route 53→Primary ❌→Secondary ✅

21 & 22. Health Checks & Failover

A Route 53 Health Check monitors the health of an endpoint. It can check whether the endpoint is responding according to the health-check configuration.

Health Check Success

Europe Server→Health Check→Healthy ✅

Route traffic to Europe.

Health Check Failure

Europe Server→Health Check→Unhealthy ❌

Route traffic to Mumbai.

23. Health Checks ≠ Zero Downtime

Health checks can improve resilience, but there can still be:

  • Detection time
  • DNS caching
  • TTL effects
  • Application-level failures that aren't detected by the chosen check

Therefore, don't interpret Route 53 failover as an absolute guarantee of zero downtime.

24. Multi-Region Architecture

A common global architecture for globally distributed applications:

Route 53 / \ / \ Europe Region Mumbai Region │ │ EC2 EC2 │ │ Application Application

29 & 30 & 31. Use Cases & Billing

29. Disaster Recovery

Primary Server → Mumbai
Backup Server → Singapore

Mumbai ❌→Health Check→Route 53→Singapore ✅

This provides a useful DNS-based failover mechanism.

30. Route 53 + S3

Route 53 can be used with supported S3 website endpoints through an Alias configuration.

example.com→Route 53→S3 Website

31. Route 53 Billing

Route 53 is a billable AWS service. Potential charges can include: Hosted zones, DNS queries, Health checks, Domain registration.

⚠️ Note Don't assume Route 53 has a general always-free tier covering all features. Pricing depends on usage/configuration.

32. Cleanup After Practice

When doing AWS practicals, always clean up resources you no longer need. Check EC2 instances in every region used.

Delete unnecessary records ↓ Delete health checks ↓ Delete hosted zone ↓ Terminate test EC2 instances

⭐ Important: A domain registered through an external registrar remains registered there even after you delete its Route 53 hosted zone.
