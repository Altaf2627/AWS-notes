🔐 SSL & TLS — Detailed and Structured Notes

1. What is SSL/TLS?

SSL (Secure Sockets Layer) and TLS (Transport Layer Security) are cryptographic protocols used to secure communication between a client and a server over a network such as the Internet.

Their main purpose is to protect sensitive information while it is being transmitted.

Example: Internet Banking

Your Computer / Browser ↓ Internet ↓ Banking Website / Server

You may send sensitive information such as: Username, Password, Account-related info, Confidential data.

If communication is not properly secured, an attacker could potentially intercept the data. SSL/TLS helps protect this communication.

2. SSL vs TLS

SSL

Secure Sockets Layer

It is the older protocol family.

TLS

Transport Layer Security

TLS is the successor to SSL and is the protocol used by modern secure connections.

🧠 Remember

People still commonly say “SSL certificate” or “SSL connection”. However, modern HTTPS connections generally use TLS, not the old SSL protocols.

SSL → Older protocol
TLS → Successor and modern protocol

3. HTTPS and the Lock Icon

When you visit a website using HTTPS, the browser indicates that the connection is protected (e.g., https://example.com).

Browsers commonly show a lock icon. Inspecting the connection reveals:

  • Connection security
  • Certificate information
  • Certificate validity
  • Certificate issuer

What does HTTPS mean?
HTTPS = HTTP Secure. It uses TLS to protect HTTP communication between the client and server.

4. What Does SSL/TLS Provide?

SSL/TLS is designed to provide important security properties for communication. The three major concepts are:

Confidentiality Integrity Authentication

These concepts are extremely important for understanding secure communication.

5. Confidentiality

Meaning: Confidentiality means that sensitive information should only be accessible to authorized parties.

Example

Imagine a confidential examination paper being transferred from a printing facility to an examination center. Only the authorized center should be able to access the contents. Someone who intercepts the transfer should not understand the contents.

Original Data ↓ Encryption ↓ Encrypted Data (Internet) ↓ Decryption ↓ Original Data

6. Integrity

Meaning: Ensuring that data has not been modified or tampered with during transmission.

Suppose the original examination paper is: DEMO

If an attacker changes it to: MO, the receiver should be able to detect that the data was modified.

Hashing and message authentication mechanisms can help detect such changes.

7. Authentication

Meaning: Verifying the identity of the party you are communicating with.

For example, when you visit a banking website, you want to know: “Am I actually communicating with the legitimate website?” Digital certificates help establish this identity.

12. Types of Encryption

The two major categories discussed are:

Symmetric Encryption Asymmetric Encryption

13. Symmetric Encryption

In symmetric encryption, the same secret key is used for both encryption and decryption.

Same Secret Key │ ↓ Plaintext → Encryption → Ciphertext │ ↓ Decryption │ ↓ Plaintext

Advantages

  • Fast and Efficient
  • Suitable for large amounts of bulk data
  • Lower computational overhead

Main Challenge

Key distribution: How do you securely share the secret key between the two parties? If intercepted, an attacker can decrypt the communication.

14. Asymmetric Encryption

Asymmetric encryption uses a pair of keys: a Public Key and a Private Key.

General Concept

Public Key ↓ Encryption Private Key ↓ Decryption

Public Key: Can generally be shared openly.
Private Key: Must be kept secret by its owner.

Server ┌─────────────┐ │ Public Key │ ← Can be shared │ Private Key │ ← Must remain secret └─────────────┘

19. What is Hashing?  |  20. Example

Hashing is the process of converting input data into a fixed-length output called a hash value or digest.

Input Data↓Hash Function↓Fixed-Length Hash

Example

Input: DEMO → Hash Function → Same Hash.

Input: MODIFIED → Hash Function → Different Hash.

A small change in input produces a completely different digest.

21. Fixed-Length Hash  |  22. Hashing and Integrity

One important property of cryptographic hash functions is that the output has a fixed size.

Small Input → SHA-256 → 256-bit digest Large Input → SHA-256 → 256-bit digest

Hashing can be used to detect whether data has changed.

Sender: Hash(Message) = H1

Receiver: Hash(Received Msg) = H2

If H1 == H2, data is consistent.

⚠️ Important

A plain hash alone does not prove who sent the message. An attacker could modify both the message and the hash. That is why authentication mechanisms such as MACs, digital signatures, and TLS's authenticated record protection are needed.

23. MD5  |  24. SHA

MD5

Message-Digest Algorithm 5.
Produces a 128-bit digest.

Considered cryptographically broken. Do not use for modern security purposes.

SHA (Secure Hash Algorithms)

Common SHA-2 variants:
SHA-256 → 256-bit digest
SHA-384 → 384-bit digest
SHA-512 → 512-bit digest

SHA-256 is commonly used in modern systems.

25. MAC  |  26. HMAC

A MAC (Message Authentication Code) is used to provide message integrity and authentication using a shared secret key.

HMAC = Hash-based Message Authentication Code. It combines a cryptographic hash function with a secret key.

Message + Secret Key ↓ HMAC ↓ Authentication Tag

Why is HMAC stronger than an ordinary hash?

Because the secret key is involved. An attacker without the secret key cannot simply modify the message and calculate a valid HMAC.

28. Digital Certificates

A digital certificate helps a browser verify the identity associated with a website's public key. When you visit a secure website, the browser inspects its certificate.

The certificate contains: Website/domain identity, Public key, Issuer, Validity period, Digital signature.

29. What is a Certificate Authority (CA)?

A Certificate Authority is a trusted organization/entity that issues digital certificates.

Website Owner ↓ Requests Certificate ↓ Certificate Authority (CA) ↓ Verifies information & Issues Digital Certificate

The browser/OS has a set of trusted root certificate authorities. This system helps the browser determine whether a certificate chain can be trusted.

30 & 31. What Does a Certificate Contain?

  • 1. Subject: Identifies the entity/domain covered.
  • 2. Public Key: Contains the associated public key.
  • 3. Issuer: Identifies the CA that issued it.
  • 4. Validity Period: Valid from & Valid until.
  • 5. Digital Signature: CA digitally signs it.
  • 6. Signature Algorithm: Used for the signature.

33. Private Key Protection

A certificate contains the public key. The private key is kept securely by the server and is not included in the certificate.

If an attacker obtains the private key, security is seriously compromised.

The TLS Handshake (Steps 38 - 44)

The overall TLS connection process establishes a secure connection between Client and Server.

Step 1 — ClientHello

Client sends supported TLS versions, cipher suites, and random/key-exchange info.

Step 2 — ServerHello

Server responds and selects compatible parameters for the connection.

Step 3 — Server Certificate

Server sends its digital certificate (containing public key and identity) to the client.

Step 4 — Certificate Verification

Browser validates the certificate chain. If valid, server identity is trusted.

Step 5 — Key Establishment

Client and server establish shared secret keying material (Modern TLS 1.3 commonly uses ephemeral Diffie-Hellman like ECDHE for forward secrecy).

Step 6 — Session Keys

Handshake produces symmetric session keys used to protect the connection.

Step 7 — Secure Communication

Application data is protected using efficient symmetric cryptography and authenticated encryption/integrity mechanisms.

46. How the Three Security Goals Are Achieved

Confidentiality: Provided through encryption (Plaintext → Encryption → Protected Data).

Integrity: Cryptographic integrity protection detects modifications (e.g., AEAD modes like AES-GCM, ChaCha20-Poly1305).

Authentication: The server's certificate helps authenticate identity.

56. 🎯 Interview Questions

Q1. What is SSL?
Secure Sockets Layer. An older crypto protocol to secure network communication.
Q2. What is TLS?
Transport Layer Security. The successor to SSL, used for modern secure internet communication.
Q4. Three major security properties of TLS?
Confidentiality, Integrity, Authentication.
Q6. What is symmetric encryption?
Uses the same shared secret key for encryption and decryption.
Q7. What is asymmetric cryptography?
Uses a public/private key pair for key establishment and digital signatures.
Q10. What is hybrid encryption?
Combines public-key cryptography (for key establishment) with symmetric cryptography (for fast bulk data protection).
Q11. What is hashing?
Converts input data into a fixed-length digest.
Q13. What is HMAC?
Keyed message authentication mechanism combining a secret key with a hash function.
Q14. What is a digital certificate?
Binds an identity/domain to a public key and is digitally signed by a CA.
Q17. What happens in a TLS handshake?
Negotiate crypto parameters, server authenticates via certificate, establish shared session keys.
