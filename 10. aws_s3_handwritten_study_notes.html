AWS S3 (Simple Storage Service)

1. Introduction to Amazon S3

Amazon S3 = Simple Storage Service

Amazon S3 is an AWS cloud-based object storage service used to store, manage, and retrieve large amounts of data.

Common Uses of S3

S3 can store:

  • Images, Videos, Documents
  • Backup files, Logs
  • Application data
  • Static website files
  • Archived data
Main Idea

S3 = Bucket + Objects

Bucket → Container where data is stored

Object → Individual file/data stored inside the bucket

2. What is an S3 Bucket?

An S3 bucket is a container used to store objects.

For example:

S3 └── Bucket ├── index.html ├── style.css ├── image1.jpg └── image2.jpg

Important Properties of a Bucket

1. Globally Unique Bucket Name: An S3 bucket name must be globally unique across AWS. It is not enough for the name to be unique only inside your account. Example: demo-bucket-abc12345

2. Region-Specific: When you create a bucket, you select an AWS Region. Example: Bucket → Stockholm Region. The bucket belongs to that selected AWS Region.

3. Objects are Stored Inside Buckets: Files uploaded to S3 are treated as objects. So remember: Bucket = Container | Object = File/Data inside the container.

3. S3 Object Model  |  4. Maximum Object Size

An S3 object can be understood using a simple Key–Value concept.

Key: The key identifies the object. Example: index.html (Key = index.html).

Value: The actual contents/data of the file are the value. Example: HTML code inside index.html.

Object ├── Key → index.html └── Value → HTML file contents

According to the course material: Maximum size of a single S3 object = 5 TB.

For very large objects, multipart upload is used/recommended. A large file can be divided into smaller parts and uploaded separately.

Large File → Parts 1-4 → S3 combines parts

Why? It makes large-file uploads easier to manage and can improve reliability.

5. S3 Data Durability and Availability

S3 is designed to provide highly reliable object storage. The transcript explains that S3 data is replicated across multiple Availability Zones (AZs) within the selected Region.

AWS Region │ ├── Availability Zone 1 ├── Availability Zone 2 └── Availability Zone 3

This helps protect data against failures affecting an individual Availability Zone.

Important

Do not confuse: Region and Availability Zone. A bucket is created in a Region, not in a specific Availability Zone.

6. Creating an S3 Bucket

Basic process: Open AWS Console → Search for S3 → Select Create bucket → Choose bucket type → Select AWS Region → Enter globally unique bucket name → Configure settings → Create bucket.

After creation, the bucket becomes a container for storing objects.

7. Uploading Files to S3

Bucket ↓ Upload ↓ Select/Review Files ↓ Upload

Inside a bucket, you can upload: Individual files, Multiple files, Folders, or use drag-and-drop. After successful upload, the objects appear inside the bucket.

8. Working with S3 Objects

After uploading an object, several operations can be performed. Common Operations: Open, Download, Delete, View properties, Change storage class, Manage versions.

For example: index.html, style.css, image.jpg. A text-based object can be opened and inspected, while an image object can be opened to view the image.

9 & 10 & 11. Hosting a Static Website on S3

One important use case of S3 is Static Website Hosting. A static website may contain: index.html, style.css, image1.jpg, image2.jpg. There is no server-side application logic required for a basic static website.

Website Structure │ ├── index.html (Main/Default) ├── style.css ├── image1.jpg └── image2.jpg

Steps to Host:

Step 1: Upload Website Files to the S3 bucket.

Step 2: Enable Static Website Hosting. (Bucket → Properties → Static website hosting).

Specify: Index document → index.html, Error document → error.html

12. Why "Access Denied" Can Occur  |  13. Block Public Access

Simply enabling static website hosting does not automatically make the objects publicly accessible. You need appropriate permissions.

Static Website Hosting
+
Public Access Permission
↓
Website Accessible
Important Warning

S3 provides Block Public Access settings. If public website access is required, the relevant public-access blocking configuration must be adjusted appropriately.

Public access should be enabled only when required. Making an S3 bucket public can expose its contents to the internet. Always understand what data is being made public before changing public-access settings.

14. S3 Bucket Policy  |  15. Important Actions

A Bucket Policy is a JSON-based policy attached to an S3 bucket. It controls: Who can access the bucket, What actions they can perform, Which resources the policy applies to. (It defines: Who can do what on which resource?)

Easy Memory Trick

GetObject → Used to retrieve/read/download an object. (s3:GetObject) | GET → Get/Read object

PutObject → Used to upload/write an object. (s3:PutObject) | PUT → Upload/Write object

16. Bucket Policy Structure

Policy │ ├── Effect → Allow / Deny ├── Principal→ Who? ├── Action → What can they do? └── Resource → Which resource?

Principal: Defines who gets permission. Action: Defines what the user/service can do (e.g. s3:GetObject). Resource: Defines the bucket/object.

17. Policy Generator  |  18. Static Website Access — Overall Flow

If you are not comfortable writing JSON manually, AWS provides a Policy Generator.

Select Type→Effect=Allow→Action→Resource→Generate→Copy JSON

19. S3 Versioning

What is Versioning?

S3 Versioning keeps multiple versions of an object.

Suppose you upload: index.html → Version 1. Then modify it and upload again: index.html → Version 2. S3 can keep both versions.

index.html ├── Version 1 └── Version 2

20. Why Versioning is Useful

Versioning helps with: Accidental overwrites, Accidental deletion, Data recovery, Maintaining previous versions, Backup-like protection.

Example: Version 1 → Old Website | Version 2 → Updated Website. If Version 2 causes a problem, you can recover/use the previous version.

21. Important Point

When versioning is enabled, new versions uploaded after enabling versioning receive version IDs. Objects uploaded before versioning was enabled may appear with: Version ID = null.

22. S3 Versioning Example  |  23. Accidental Deletion

Upload index.html→Version 1→Modify/Upload→Version 2→Modify/Upload→Version 3 (Current)

S3 maintains the different versions. The latest version is normally used as the current object.

Key Concept Versioning = Protection against accidental changes/deletion. If the current version is removed, an earlier version may still be available depending on the deletion operation and versioning state.

24. S3 Replication

S3 supports automatic replication of objects between buckets. Two important scenarios are:

1. Same-Region Replication

Data can be replicated between buckets in the same AWS Region.

Primary Bucket ↓ Replication ↓ Secondary Bucket

2. Cross-Region Replication

Objects can be replicated to a bucket in another AWS Region.

Mumbai Region (Primary) ↓ Cross-Region Replication ↓ Europe Region (Secondary)

25. Why Use S3 Replication?

Common use cases include:

  • Backup: Maintain another copy of important data.
  • Disaster Recovery: If the primary location has problems, another copy exists elsewhere.
  • Geographic Data Access: Data can be replicated closer to users in another geographical region.

26. Requirements  |  27. Practical Flow  |  28. Existing Objects

A destination bucket must already exist before replication can be configured. Replication is generally configured using a replication rule. (Source Bucket → Replication Rule → Destination Bucket). You can configure replication for all objects or specific objects/prefixes.

27. Practical Flow

Create destination bucket → Enable versioning → Open source bucket → Management → Create replication rule → Select source scope → Select destination bucket → Configure IAM role/permissions → Configure options → Save rule.

28. Existing vs New Objects

When configuring replication, there can be an option/process for handling existing objects as well as objects uploaded after the rule is created. Existing Objects + Future Objects. The exact behavior depends on the configuration.

29. S3 Storage Classes

AWS provides different S3 Storage Classes. Why? Because different types of data have different: Access frequencies, Retention requirements, Performance requirements, Cost requirements. Choose the storage class according to your workload.

30. S3 Standard

Use Case: Frequently accessed data (website files, app data).
Characteristics: High durability, high availability, low latency.

31. S3 Intelligent-Tiering

Automatically moves data between appropriate access tiers based on usage patterns. Frequent Access → suitable tier, Infrequent Access → lower-cost tier. Best when access patterns are unknown.

32. S3 Standard-IA

IA = Infrequent Access. Used for data that must remain readily available but is accessed less frequently (e.g., occasional backups). Lower storage cost, but retrieval charges apply.

33. S3 One Zone-IA

Designed for infrequently accessed data where lower storage cost is important and data can tolerate a single AZ. Use Case: Non-critical or reproducible data (temporary logs, secondary copies). Do not choose blindly for critical data.

34. S3 Glacier

Designed for long-term archival. Good for data that is rarely accessed and needs long-term retention (old records, historical data).

35. S3 Glacier Deep Archive

Designed for very long-term archival with very low storage cost. Example: Compliance records retained for many years.

36. S3 Outposts

S3 Outposts provides S3 storage capabilities using AWS infrastructure deployed through AWS Outposts for workloads that require local/on-premises data residency or processing characteristics.

Memory Trick
Frequent→Standard | Less Frequent→Standard-IA | Rare→Glacier | Very Long-term→Deep Archive

37. Storage Class Selection

A simple decision-making approach:

Requirement Suitable Class
Frequently accessed dataS3 Standard
Unknown/changing access patternS3 Intelligent-Tiering
Infrequently accessed dataS3 Standard-IA
Infrequent, non-critical/re-creatable dataS3 One Zone-IA
Long-term archiveS3 Glacier
Very long-term archive/complianceS3 Glacier Deep Archive
AWS Outposts local storage use caseS3 Outposts

Always check current AWS pricing and storage-class conditions before making a production decision.

38. S3 Lifecycle Rules

What is a Lifecycle Rule? An S3 Lifecycle rule automatically manages objects as they age or become less relevant. It can: Transition objects between storage classes, Expire/delete objects, Manage old versions in versioned buckets.

39. Example Lifecycle Policy

Suppose website data is frequently accessed for the first month:

Day 0 → S3 Standard ↓ After 30 days → S3 Standard-IA ↓ After 60 days → S3 One Zone-IA / lower-cost tier ↓ After 90 days → Archive storage ↓ After required retention period → Delete

40. Benefits of Lifecycle Rules

  • Reduce Cost: Old data automatically moves to cheaper storage.
  • Automate Data Mgmt: No manual moving needed.
  • Manage Retention: Data automatically expires.
  • Operational Efficiency: Upload → Store → Transition → Archive → Delete (automatic).

41. S3 Glacier — Key Idea  |  42. S3 Storage Cost Concept

Think of Glacier as: Cold/Archive Storage. It is suitable when data is stored mainly for retention rather than frequent access. (Historical records, backup archives, compliance data).

42. S3 Storage Cost Concept: S3 costs depend on factors such as amount of data stored, storage class, requests, data retrieval, data transfer, and lifecycle/replication configs. More data + more operations can mean higher cost. Lifecycle rules and appropriate classes help optimize costs.

AWS Snow Family (43 - 48)

The AWS Snow Family is used for moving large amounts of data and for certain edge-computing use cases. It becomes useful when transferring huge datasets over the internet would be: Too slow, Difficult, Expensive, Operationally challenging.

Concept: Imagine an organization has 10 TB of data. Uploading over internet takes too long. AWS provides physical devices to transfer data.

Your Data Center→AWS Snow Device→Ship Device to AWS→AWS imports data to S3

45. Snowcone

Snowcone is a small and portable device intended for smaller-scale data transfer and edge use cases.
Memory: Snowcone = Small + Portable

46. Snowball

Snowball is a larger device designed for transferring much larger quantities of data. Supports some edge computing.
Memory: Snowball → Larger

47. Snowmobile

Snowmobile is designed for extremely large-scale data transfers. Think of it as a massive data-transfer solution (truck/container-scale) for very large datasets.
Memory: Snowcone (Small) → Snowball (Large) → Snowmobile (Massive)

49 & 50 & 51. AWS Storage Gateway

AWS Storage Gateway is a hybrid cloud storage service. Hybrid Cloud Meaning: A hybrid environment combines: On-Premises Infrastructure + AWS Cloud.

Suppose a company has an On-Premises Application in a Local Data Center but wants to use AWS storage services. Storage Gateway can provide a bridge between on-premises environments and AWS storage.

On-Premises Application ↓ Storage Gateway ↓ AWS Storage

51. Storage Gateway Types:

  • File Gateway: File-based access to AWS storage.
  • Volume Gateway: Block-storage-oriented functionality.
  • Tape Gateway: Virtual tape for backup/archive workflows.

52. S3 vs Snow Family vs Storage Gateway

53 & 54. S3 Encryption & Security Concepts

Data security is an important part of S3. Encryption protects data by making it unreadable without the appropriate decryption mechanism. S3 supports encryption options for protecting data at rest.

Data→Encryption→Protected Storage

54. S3 Security Areas: Block Public Access, Bucket Policies, IAM Permissions, Encryption, Versioning.

57. Important Interview Questions

Q1. What is Amazon S3?
Amazon S3 is an AWS object storage service used to store, manage, and retrieve large amounts of data.
Q2. What is an S3 bucket?
A bucket is a container used to store S3 objects.
Q3. What is an S3 object?
An object is an individual piece of data/file stored inside an S3 bucket.
Q4. Difference between bucket and object?
Bucket → Container | Object → File/Data inside the container
Q5. Must an S3 bucket name be unique?
Yes. The bucket name must be globally unique.
Q6. What is S3 Versioning?
Versioning allows S3 to maintain multiple versions of an object.
Q7. Why is versioning useful?
Protects against accidental overwrites/deletions and allows previous versions to be recovered.
Q8. What is a Bucket Policy?
A JSON-based resource policy used to control access to an S3 bucket and its objects.
Q9. What does GetObject mean?
It allows retrieval/read access to an S3 object.
Q10. What does PutObject mean?
It allows an object to be uploaded/written to S3.
Q11. What is S3 Lifecycle?
A lifecycle config automatically transitions or expires objects based on rules such as age.
Q12. Why are different Storage Classes available?
To optimize storage according to: Access frequency, Retention period, Retrieval requirements, Cost.
Q13. What is S3 Intelligent-Tiering?
A storage class designed to automatically optimize storage costs based on changing access patterns.
Q14. What is S3 Glacier used for?
Long-term archival and rarely accessed data.
Q15. What is Glacier Deep Archive?
A very low-cost storage option intended for long-term archival and retention.
Q16. What is S3 Replication?
It automatically copies eligible objects from a source bucket to a destination bucket.
Q17. What is Cross-Region Replication?
Replication of objects from a bucket in one AWS Region to a bucket in another Region.
Q18. What is the Snow Family?
Provides physical devices/services for large-scale data transfer and edge-computing.
Q19. What is AWS Storage Gateway?
A hybrid cloud storage service that connects on-premises environments with AWS storage.
