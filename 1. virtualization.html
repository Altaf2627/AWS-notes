KEY TOPIC

1. Introduction to Virtualization

Virtualization is one of the most commonly used concepts in the IT industry, especially in:

✔ Cloud Computing
✔ AWS
✔ DevOps
✔ Data Centers
✔ Server Management
✔ Software Dev & Testing
Simple Definition:
Virtualization is the process of creating virtual versions of computing resources such as computers, servers, storage, or networks using software.

👉 Instead of purchasing a separate physical computer for every requirement, we can use one physical machine to create multiple Virtual Machines (VMs).

2. Understanding a Physical Computer

Let's first understand a normal laptop or desktop. A physical computer generally contains:

Hardware Components:
  • CPU → Processes instructions
  • RAM → Temporary memory
  • Hard Disk / SSD → Permanent storage
  • Network interface
  • Other hardware components
Operating System (OS):

Above the hardware, we install an OS:
• Windows   • Linux   • macOS

The operating system manages the hardware and provides an environment for applications to run.

Traditional Architecture (Without Virtualization)
Applications
↓ (runs on)
Operating System (Windows / Linux)
↓ (manages)
Hardware (CPU + RAM + Storage)
SCENARIO

3. Why Do We Need Virtualization?

Imagine you are a software engineer developing an application. You may need to test your application on different operating systems: Windows, Ubuntu, Red Hat Linux, and other Linux distributions.

Without Virtualization:

Computer 1 → Windows | Computer 2 → Ubuntu | Computer 3 → Red Hat | Computer 4 → Another OS

❌ Expensive
❌ Difficult to maintain
❌ Requires more physical space
❌ Requires more hardware
With Virtualization:

You can use one physical computer and create multiple virtual machines!

✔ 1 Physical Computer runs multiple OS
✔ Scalable, cost-effective & easy
✔ Instant start/stop & cleanup

Therefore, one physical machine can run multiple operating systems simultaneously.

CORE CONCEPT

4. What is a Hypervisor?

The virtualization layer that enables us to create and manage Virtual Machines is called a Hypervisor.

Definition:
A Hypervisor is software (or firmware/software layer) that creates, runs, and manages Virtual Machines. It allows multiple virtual machines to share the physical hardware resources of a computer.

Main Responsibilities of a Hypervisor:

• Create Virtual Machines
• Allocate CPU resources
• Allocate RAM
• Allocate storage
• Manage Virtual Machines
• Start / stop VMs
• Isolate VMs from each other
• Allow multiple OS on same physical PC

5. Example — Oracle VirtualBox

One common example of a hypervisor is: Oracle VirtualBox. It is commonly used for learning and testing virtualization on personal computers.

Setup Flow: Physical Computer ➔ Windows (Host) ➔ VirtualBox ➔ (VM 1: Ubuntu & VM 2: Linux)
No OS Replacement Needed!

You can run a Linux-based VM on your Windows computer without replacing Windows.

HOW IT WORKS

6. How Does a Hypervisor Work?

The key concept is: A hypervisor shares the physical hardware resources among multiple Virtual Machines.

Resource Allocation Example (Physical ➔ Virtual)
Physical Computer
RAM: 8 GB
Storage: 100 GB
➔ [ Hypervisor ] ➔
VM 1: 2 GB RAM | 20 GB Storage
VM 2: 2 GB RAM | 10 GB Storage

*The remaining resources can be used by the host system or allocated elsewhere.

⚠️ Important: The resources assigned to the VM ultimately come from the physical hardware. A VM doesn't magically create physical RAM or storage.

7. What is a Virtual Machine?

A Virtual Machine (VM) is a software-based representation of a physical computer. It behaves like an independent computer even though it runs on another machine.

• Virtual CPU (vCPU)
• Virtual RAM (vRAM)
• Virtual Hard Disk (vDisk)
• Virtual Network Interface (vNIC)
• Operating System & Applications

8. Why "Virtual" Machine?

A physical computer actually exists as physical silicon hardware.
A Virtual Machine is created using software.

Key Takeaway: A VM behaves like a computer, but it is created using software rather than being a separate physical machine.

9. Virtual Machine Example

Suppose your laptop runs Windows and you want to learn Linux. Instead of buying another laptop:

Your Laptop (Windows) ➔ Hypervisor ➔ [ Ubuntu VM ➔ Linux ]

Now you can use Ubuntu inside your Windows computer. You can also create another VM simultaneously!

TESTING BENEFIT

10. Virtualization and Software Testing

Virtualization is extremely useful for software developers and testers. Suppose an application needs testing across Windows, Ubuntu, and Linux:

One Physical Computer ➔ Hypervisor ➔ [ Windows VM | Ubuntu VM | Linux VM ]

The developer can seamlessly test the application in different environments.

✅ No need for multiple physical computers
✅ Easy to create testing environments
✅ Easy to delete / recreate VMs
✅ Reduces hardware costs
✅ Useful for continuous development and testing workflows
CRITICAL EXAM POINT

11. Isolation — An Important Feature

One of the most important benefits of virtualization is isolation. Each VM generally operates in its own isolated environment.

Example Scenario:
Suppose: VM1 → Testing environment | VM2 → Development environment.
If something goes wrong or you install something problematic inside VM1, it generally doesn't directly affect the OS or applications running inside VM2!

Isolation makes virtualization ideal for testing, development, security boundaries, and multi-tenant environments.

*Note: Isolation is strong, but it isn't an absolute guarantee against every possible failure or hardware vulnerability.

12. Host Operating System & Guest Operating System

In some virtualization setups, the physical computer already has an operating system installed:

Host OS:

The operating system installed directly on the physical computer.
Example: Windows (on your laptop).

Host OS = OS of the physical / main machine.
Guest OS:

The operating system installed inside the Virtual Machine.
Example: Ubuntu Linux (inside VM).

Guest OS = OS running inside a VM.

14. Type 2 — Hosted Hypervisor

A Type 2 Hypervisor runs on top of an existing host operating system. It is installed just like normal application software.

ENTERPRISE STANDARD

15. Type 1 — Bare Metal Hypervisor

A Type 1 Hypervisor runs directly on the physical hardware. There is no traditional host operating system sitting underneath it.

👉 This is why it is called a Bare Metal Hypervisor: because the hypervisor software is installed directly onto the raw physical server hardware.
COMMON CONFUSION

16. How Can Type 1 Work Without an Operating System?

A common beginner question! A Type 1 hypervisor doesn't require desktop Windows or Ubuntu. Instead, the hypervisor itself acts as a specialized operating layer with built-in low-level kernel drivers to:

✔ Access & schedule CPU
✔ Manage RAM memory directly
✔ Control physical storage disks
✔ Handle low-level networking

You can think of it as an ultra-lean specialized OS designed strictly for virtualization efficiency.

17. Examples of Type 1 Hypervisors

VMware ESXi

Widely used in enterprise enterprise data centers globally.

Microsoft Hyper-V

Core virtualization in Windows Server infrastructure.

Citrix Hypervisor

Optimized for server and desktop virtual infrastructure.

*Cloud providers (AWS, Azure, GCP) use custom bare-metal hypervisor architectures to efficiently provide multi-tenant compute resources.

CLOUD FOUNDATION

18. Virtualization in Cloud Computing

Virtualization is the core foundational technology powering modern cloud providers like AWS, Azure & GCP.

Large Physical Server ➔ Hypervisor ➔ [ VM (User A) | VM (User B) | VM (User C) ]

A large physical server is partitioned into multiple isolated virtual computing environments without customers needing to buy servers.

19. Why Do Cloud Providers Use Virtualization?

1. Better Resource Utilization: Physical resources are shared across thousands of customers simultaneously.
2. Scalability: Users can instantly scale up CPU/RAM as app traffic surges.
3. Cost Efficiency: Pay-as-you-go instead of capital datacenter expenditure.
4. Strict Multi-Tenant Isolation: Users cannot view or interfere with other tenants' data.
5. Flexibility: VMs can be launched, resized, snapshotted, migrated, and destroyed in seconds.

20. Virtualization in Organizations

Large enterprises run private on-premise data centers. Instead of a dedicated box per role:

Application Server Database Server Dev Environment Testing Environment Internal Tools Monitoring System

Far more cost and power-efficient than purchasing 6 separate physical server boxes!

EXAM ESSENTIAL

21. Major Benefits of Virtualization

1. Cost Reduction 💰

Fewer physical machines needed. Drastically reduces: Hardware costs, Datacenter real estate space, Power consumption, Cooling bills, Maintenance staff.

2. Better Resource Utilization

Traditional servers average only 10-15% CPU load. Virtualization stacks workloads to achieve 70-80% hardware efficiency.

3. Scalability

Dynamic resource adjustments: 2 GB RAM ➔ 4 GB RAM ➔ 8 GB RAM in clicks without physical upgrades.

4. Flexibility

Run diverse environments concurrently: VM1 (Ubuntu), VM2 (Windows), VM3 (Dev), VM4 (Testing).

5. Isolation

Crashes or virus infections in one VM remain quarantined and do not bring down neighboring machines.

6. Easy Testing & 7. Management

Spin up sandbox VMs, test destructive code, revert with snapshots. Centralized dashboard control.

24. Important Terminology Quick-Glance

Host Machine: The physical computer/server running virtualization.

Guest OS: The OS installed and running inside the VM.

27. Real-World Example Walkthrough

Scenario: You have a laptop with 8 GB RAM + 100 GB SSD + Windows. You want to learn Linux.

• With Virtualization: You install a hypervisor on your existing Windows setup:

Laptop (8GB RAM, 100GB SSD, Windows) ➔ Hypervisor ➔ [ Ubuntu VM (2GB RAM, 20GB Disk) + Another VM (2GB RAM, 10GB Disk) ]

28. Virtualization vs Cloud Computing

These two concepts are intimately related but are not identical:

Virtualization:

A foundational technology that allows physical resources to be abstracted into virtual slices.

Cloud Computing:

A broader business & service model delivering on-demand computing over the network/Internet.

💡 Easy Analogy: Virtualization = How resources are sliced & isolated | Cloud = How resources are packaged & billed as a service!
⭐ EXAM SUMMARY

Key Concepts to Remember

1. Virtualization: Creating software versions of resources.
2. Virtual Machine: Software computer on physical hardware.
3. Hypervisor: Creates, allocates & manages VMs.
4. Host: Physical machine running virtualization.

6. Type 1: HW ➔ Hypervisor ➔ VM
7. Type 2: HW ➔ Host OS ➔ Hypervisor ➔ VM

Ans: A technology allowing us to create virtual versions of computing resources, such as servers or computers, using software.

Ans: Divides infrastructure into isolated environments for better resource utilization, flexibility, scalability, and cost efficiency.

Q8. Difference between Host OS & Guest OS?
