GETTING STARTED

1. Introduction

Before starting hands-on practice with AWS, the first step is to create and configure an AWS account.

An AWS account allows you to:

• Access AWS services
• Create cloud resources
• Practice services such as EC2, S3, VPC, IAM, etc.
• Monitor resource usage and costs
• Deploy applications
• Learn AWS through the AWS Management Console
⚠️ Important Warning: AWS may require valid payment and identity verification. Never use fake identity or payment information.
PREREQUISITES

2. Requirements for Creating an AWS Account

You generally need the following four items:

1. Working Email Address 📧

Your email address should:

  • Be accessible to you
  • Be a valid email address
  • Be available for verification
  • Be used to receive AWS account notifications

AWS sends verification emails during account creation.

2. Working Mobile Number 📱

A valid mobile number is required for verification.

AWS may send an OTP or use phone verification to confirm your identity.

Enter Mobile ➔ Receive SMS/Call OTP ➔ Verified ✓
3. Valid Identity Document 🪪

AWS may require identity verification. Depending on the verification process and country, an accepted government-issued ID may include:

• Driving License
• Passport
• Other supported government-issued ID

Note: The exact documents accepted can vary depending on AWS's current verification process and your location.

4. Credit/Debit Card 💳

AWS requires valid payment information for account verification and billing. You should provide:

• Valid debit card, or
• Valid credit card
Security Rule: Do not use fake card details.

3. Why Does AWS Ask for Payment Information?

COMMON FAQ

A common beginner question is: "If AWS has a Free Tier, why does it ask for my card?"

Answer: Because AWS is a paid cloud platform. The Free Tier allows eligible customers to use certain services/resources within specified limits, but AWS still needs a valid payment method for account verification and for situations where chargeable usage occurs.

EC2 Example:
Suppose you create an EC2 instance:
• If usage remains within an applicable free allowance ➔ You may not be charged.
• But if you exceed allowance, run longer than allowed, or choose paid features ➔ Charges may occur!
Important Rule to Remember:
Do not assume: "AWS Free Tier = Everything is free."
Instead remember:
Free Tier = Specific services + specific usage limits + specific eligibility conditions.
Always check current AWS pricing/free-tier terms before creating resources.

4. AWS Account Creation — Basic Flow

The Complete Signup Pipeline

The general signup process is structured as follows:

AWS Website ➔ Create AWS Account ➔ Enter Email ➔ Verify Email
➔ Create Password ➔ Account Info ➔ Payment Info ➔ Identity Verification
➔ Phone Verification ➔ Select Support Plan ➔ Complete Signup ➔ Sign in to Console ✓

5. Step 1 — Visit AWS

URL

Go to the official AWS website: aws.amazon.com

Choose the option to create/sign up for an AWS account. Look for the button:

Create an AWS Account / Create a Free Account

AWS may change the wording or signup interface over time.

6. Step 2 — Enter Your Email Address

COMMUNICATION

Enter a valid email address. AWS will use this email for:

• Verification
• Account communication
• Billing notifications
• Security alerts
• Important AWS notifications
Important: Use an email account that you regularly access.

7. Step 3 — Verify Email

SECURITY

AWS sends a verification code/link to your email.

Enter Email ➔ AWS sends code ➔ Open Email ➔ Enter Code ➔ Email Verified ✓

After successful verification, you can continue the signup process.

8. Step 4 — Create AWS Account Password

CREDENTIALS

Create a strong password according to AWS's current password requirements.

Good Practice:
• Uppercase letters
• Lowercase letters
• Numbers
• Special characters
Avoid:
• Your name
• Birthday
• Simple passwords
• Reused passwords

9. Step 5 — Provide Account Information

AWS asks for information required to create the account. You may need to provide details such as:

• Name
• Contact information
• Address
• Country / region
• Phone number
• Account type / purpose

👉 For learning purposes, select the appropriate personal option if that accurately describes your use.

10. Step 6 — Add Payment Information

Enter your valid Debit card, or Credit card. AWS uses this information for billing and account verification.

Temporary Verification Charge:
AWS may place a small temporary authorization/verification charge on the card. The exact amount and whether/how quickly it is reversed can vary by region, bank, card network, and AWS's current verification process.

⚠️ Important: Do not rely on a specific amount such as ₹2 as a universal rule.

14. Step 10 — Account Creation Completed

ACTIVATED

After completing all required verification steps, AWS activates the account.

You will receive an email confirming that your: AWS services are ready to use.

You can then immediately sign in to the AWS Management Console!

PORTAL

15. AWS Management Console

Graphical Web-Based Portal

The AWS Management Console is a web-based graphical interface used to manage AWS resources and services. Instead of using commands, you can perform many AWS operations through the browser.

Using the console, you can:

Launch EC2 instances Create S3 buckets Configure VPCs Create IAM users & roles View CloudWatch metrics Manage databases (RDS) Configure load balancers Monitor billing & costs

16. AWS Console — Dashboard

After signing in, you see the AWS Console. The dashboard provides access to:

• Recently visited services
• AWS services catalog
• Region selection
• Cost and usage info
• Account-related shortcuts & resources

For a new AWS account, dashboard looks empty initially because you haven't used services yet.

17. Recently Visited Services

AWS Console keeps track of services you recently accessed. For example:

EC2 S3 IAM VPC RDS

This makes it fast and easy to return to frequently used services without searching.

20. AWS Region Selection

One of the most important concepts in the AWS Console is the Region. The console displays the currently selected AWS Region in the top-right corner:

• Europe (Stockholm)
• ap-northeast-1 (Tokyo)
• Asia Pacific (Mumbai)

The exact selected region depends on your session and what you choose.

21. What is an AWS Region?

Definition: An AWS Region is a geographical area where AWS operates infrastructure (India, US, Europe, Asia Pacific, Middle East, Canada, Australia).

Mumbai Region Identifier:
Asia Pacific (Mumbai) = ap-south-1

Each region has a distinct, standardized alphanumeric identifier code.

VERY IMPORTANT

22. Why Does Region Matter?

When creating AWS resources, you select a region. The resource is created in that selected region!

Created in Mumbai ➔ Switch to Singapore ➔ EC2 Instance disappears from view! 😱
Common Beginner Panic: "I created my EC2 instance, but now I can't find it!"
➔ You didn't lose it! You are simply looking at a different region in the console dropdown.

23. Choosing a Region (5 Factors)

Region selection depends on application requirements:

1. Latency: Choose geographically closer regions to users (Indian Users ➔ Mumbai Region = low latency).
2. Compliance: Strict legal data-residency laws requiring data to remain inside the country.
3. Service Availability: Not every AWS service/feature is available in every region.
4. Cost: Pricing differs slightly across AWS regions.
5. Disaster Recovery: Multi-region strategies for high availability.

HIERARCHY

24. Region vs Availability Zone (AZ)

Resilience & Isolation

Remember this fundamental architecture hierarchy:

AWS Global Infrastructure ➔ Region ➔ [ Availability Zone 1 | Availability Zone 2 | Availability Zone 3 ]
Example: Mumbai Region (ap-south-1) ➔ [ ap-south-1a | ap-south-1b | ap-south-1c ]
Region:
A geographical area containing multiple Availability Zones. Used for geographic deployment.
Availability Zone (AZ):
A separate, isolated infrastructure location / data center within a Region. Designed for high availability, auto-scaling & disaster recovery.

29. Important Security Practices

CRITICAL

After creating your account, security is top priority:

1. Enable MFA: Multi-Factor Authentication adds an essential second defense layer beyond passwords.
Password + MFA Code ➔ Strong Security
2. Never Share Credentials: Never share Password, Access keys, Secret access keys, MFA codes, or OTPs.
3. Use IAM Properly: Avoid using the root user for everyday administrative or lab tasks.

30. Root User vs IAM User

KEY DISTINCTION
Root User:
The original AWS account identity created with email. Has unrestricted, complete permissions over everything in the account.
IAM User / Role:
Identities created inside IAM with strictly controlled, granular permissions to specific resources.
Industry Best Practice: Use the root user ONLY when root-level setup is required, and use IAM identities for all regular tasks.

31. Common Beginner Mistakes (Avoid These Traps!)

WATCH OUT
Mistake 1 — Assuming Everything Is Free
❌ "AWS is free."
✅ "Some AWS usage may be free within applicable limits & conditions."
Mistake 2 — Forgetting the Region
Create EC2 in Mumbai, then switch to Oregon.
"My EC2 disappeared!" No, it's just in Mumbai!
Mistake 3 — Leaving Resources Running
EC2 launched ➔ practice done ➔ forgot to terminate ➔ bills pile up silently on your credit card.
Mistake 4 — Creating Unnecessary Expensive Resources
Creating multiple EC2 instances, Elastic IPs (charged when unattached!), NAT Gateways, Load Balancers, or RDS without understanding costs. Start small!
Mistake 5 — Ignoring Billing
Never checking AWS Billing & Cost Management dashboard until an invoice notification arrives.

35. Interview Questions & Exact Answers (Part 1)

Q1. What is the AWS Management Console?

Ans: A web-based graphical interface that allows users to access, configure, monitor, and manage AWS services and resources through a browser.

Q2. Why does AWS require payment information?

Ans: For identity verification and billing. Even with Free Tier, charges occur when paid resources or usage beyond free allowances are consumed.

Q3. Is AWS completely free?

Ans: No. AWS is a paid platform. Free Tier offers exist under specified limits/conditions, but usage outside those conditions generates charges.

Q4. What is an AWS Region?

Ans: A geographical area containing AWS infrastructure and multiple isolated Availability Zones (e.g. Mumbai ap-south-1).

Q5. Why is region selection important?

Ans: It determines where resources are created and directly impacts network latency, service availability, compliance laws, and pricing.

Q6. What happens if you switch AWS Regions?

Ans: Region-specific resources won't appear in the new region's console view. An EC2 instance created in Mumbai won't show in Singapore.

INTERVIEW FINALE

35. Interview Questions & Answers (Part 2)

Q7. What is an Availability Zone?

Ans: An isolated infrastructure location containing one or more discrete data centers within an AWS Region, designed to provide resilience and support high availability.

Q8. Why should AWS resources be stopped or deleted after practice?

Ans: AWS resources generate ongoing charges while they remain active or provisioned. Cleaning up unused resources prevents unexpected monthly billing charges.

Q9. What is MFA?

Ans: Multi-Factor Authentication. It adds a crucial second verification factor (such as a time-based TOTP code) beyond the password, dramatically improving account defense.

Q10. What is IAM?

Ans: Identity and Access Management. It controls authentication (who can sign in) and authorization (what permissions and resources they can access) in AWS.
