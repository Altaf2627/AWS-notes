AWS EBS — ELASTIC BLOCK STORE
Detailed & Revision-Friendly Notes

1. Introduction to EBS

EBS = Elastic Block Store

Amazon EBS (Elastic Block Store) is a cloud-based storage service designed to work with EC2 instances.

Simple Definition

EBS is like a virtual hard drive that can be attached to an EC2 instance.

It can be used to:

  • Store application data
  • Store files
  • Provide additional disk space
  • Maintain persistent data
  • Take backups using snapshots
  • Attach additional storage to an EC2 instance
Real-Life Example

Think of EBS like an external hard drive.

Laptop
↓
External Hard Drive

Similarly:

EC2 Instance
↓
EBS

You can attach storage to an EC2 instance and use it for storing data.

2. Why is EBS Important?

Suppose you have an EC2 instance containing important data.

EC2 Instance
| ↓
Application + Data

If the EC2 instance is terminated, you may still want the data to remain available.

EBS can provide persistent storage separate from the compute instance, depending on how the volume is configured.

Important Benefits
  • Additional storage
  • Persistent storage
  • Backup through snapshots
  • Ability to attach multiple volumes
  • Ability to increase volume size
  • Encryption support
  • Data redundancy within an Availability Zone
  • Useful for database workloads

3. EBS and EC2

EBS is closely associated with EC2.

When launching an EC2 instance, storage can be configured.

Example:

EC2 Instance | └── EBS Volume └── 8 GB

The transcript demonstrates an EC2 instance launched with an 8 GB GP3 EBS volume.

A useful way to understand EBS is: EBS ≈ Virtual Hard Drive

5. Multiple EBS Volumes

An EC2 instance can have multiple EBS volumes attached to it.

Example:

EC2 | ┌──────┴──────┐ ↓ ↓ EBS 1 EBS 2 8 GB 5 GB

This can be useful when an application requires additional storage.

6. EBS Use Case — Database

EBS can be useful when hosting databases that require reliable storage.

Examples mentioned in the transcript include:

  • MySQL
  • PostgreSQL

For database workloads, storage performance can be important because databases can perform many input/output operations.

7. Important EBS Characteristics

7.1 Region and Availability Zone Specific

One of the most important concepts is that an EBS volume is associated with a specific Availability Zone.

Example:

Region | ├── AZ-A ├── AZ-B └── AZ-C

Suppose: EBS → AZ-B

If you create an EC2 instance in: AZ-C, you cannot directly attach that EBS volume to the instance because they are in different Availability Zones.

Key Point EC2 instance and EBS volume need to be in the same Availability Zone for direct attachment.

8. EBS Built-in Redundancy

EBS provides redundancy within its Availability Zone.

The transcript explains that data is replicated within the Availability Zone so that failure of an individual storage block does not necessarily result in data loss.

Important Limitation

This does not mean that your data is automatically protected from an entire Availability Zone failure.

If the entire Availability Zone fails, additional backup mechanisms are needed.

Therefore:

EBS Redundancy
↓
Protection within AZ

For stronger disaster recovery:

EBS
↓
Snapshot
↓
Backup / Other AZ / Other Region

9. EBS Volume Types

AWS provides different EBS volume types for different workloads.

The transcript discusses examples such as:

  • GP2
  • GP3
  • io1
  • io2

9.1 GP2 / GP3

GP = General Purpose

General-purpose volumes are suitable for many common workloads.

The transcript demonstrates GP3 while launching an EC2 instance.

Suitable for:

  • Normal applications
  • General workloads
  • Common EC2 storage requirements

9.2 io1 / io2

These are designed for workloads requiring high I/O performance.

Suitable for:

  • High-performance applications
  • Heavy input/output workloads
  • Workloads requiring high IOPS
Easy Memory Trick

GP → General Purpose

io → High I/O performance

10. Performance and Cost

Higher performance generally comes with higher cost.

For example, if an application performs a very large number of I/O operations, a high-performance EBS volume may be appropriate.

Remember

More performance → potentially higher cost

Always choose storage based on the actual workload.

11. EBS Encryption

EBS volumes can be encrypted.

Purpose: Encryption helps protect data and provides additional security.

The transcript explains encryption for:

  • Data stored on the volume
  • Data transferred between the EBS volume and EC2
  • Snapshots
  • Volumes created from encrypted snapshots

12. EBS Encryption — Concept

EC2 ↕ Encrypted Transfer ↕ EBS Volume | Encrypted Data

When encryption is enabled, data is protected while stored and during relevant transfers.

The transcript refers to AES-256 encryption and AWS Key Management Service (KMS) for key management.

13. Resizing an EBS Volume

One of the useful features of EBS is that the volume size can be increased.

Example: Initial size: 5 GB  →  Increase it to: 6 GB

The transcript demonstrates this through: Volumes → Actions → Modify Volume

Important Points (According to the transcript):

  • The volume size can be increased.
  • The EC2 instance does not need to be restarted for the volume modification itself.
  • The change can be detected quickly by the operating system.

Example:

Before: EBS = 5 GB
↓ Modify
After: EBS = 6 GB

14. Important: Resizing vs Filesystem

Increasing the EBS volume size does not automatically mean every filesystem/application immediately uses the newly available space.

Depending on the operating system and filesystem, additional filesystem-level steps may be required.

The transcript mentions LVM (Logical Volume Manager) as another topic for managing storage.

15. Delete on Termination

This is a very important EC2 + EBS concept.

When you launch an EC2 instance, its attached EBS volume can have a setting called: Delete on Termination

It determines whether the EBS volume is deleted when the EC2 instance is terminated.

If Delete on Termination = YES

EC2 Terminated
↓
EBS Deleted
↓
Data Lost

The transcript demonstrates this behavior.

If Delete on Termination = NO

EC2 Terminated
↓
EBS Remains
↓
Data/Volume Available

The EBS volume remains available and can potentially be attached to another appropriate EC2 instance.

16. How to Change Delete on Termination

During EC2 launch:

Launch EC2
↓
Configure Storage
↓
Advanced Options
↓
Delete on Termination

You can turn the setting off when you want the volume to remain after EC2 termination.

26. EBS Snapshot

What is a Snapshot?

An EBS Snapshot is a point-in-time backup of an EBS volume.

Main Purpose:

Snapshot = Backup of an EBS volume

27. Why Use Snapshots?

Suppose your EBS volume contains important data:

EBS | ├── Files ├── Application Data └── Database Data

You create a snapshot:

EBS
↓
Snapshot

If the original volume is later damaged or deleted, the snapshot can be used to create a new EBS volume.

Snapshot
↓
New EBS Volume
↓
New EC2

28. Snapshot Use Cases

Snapshots can be used for:

1. Backup
Protect data against accidental deletion or volume failure.

2. Recovery
Create a new EBS volume from the snapshot.

3. Moving Data Between Availability Zones
Create a snapshot and use it to create a volume in another Availability Zone.

4. Moving Data Between Regions
Copy the snapshot to another AWS Region.

38. EBS Lifecycle Manager

What is EBS Lifecycle Manager?
EBS Lifecycle Manager can automate the management of EBS snapshots.

The transcript describes it as a way to automate: Snapshot creation, Snapshot retention, Snapshot copying, Snapshot deletion.

39. Why Use Lifecycle Manager?

Imagine you have important data and want: Daily backups
Doing this manually every day is inconvenient.

Instead:

EBS
↓
Lifecycle Manager
↓

40. Snapshot Frequency

A lifecycle policy can define how frequently snapshots should be created.

Examples: Daily, Based on a defined schedule.

The transcript demonstrates a schedule involving snapshot creation every 12 hours.

41. Snapshot Retention

Retention determines how long snapshots should be kept.

Example:

Create Snapshot
↓
Keep for 10 days
↓
Delete after retention period

This prevents unlimited accumulation of old snapshots.

42. Retention by Count or Age

The transcript describes retention options based on:

Count: Keep a certain number of snapshots.

Age: Keep snapshots for a defined period. Examples of periods can include: Days, Weeks, Months, Years.

47. EBS Cost Considerations

EBS and related storage features can incur charges depending on:

  • Volume type
  • Storage size
  • Provisioned performance
  • Snapshots
  • Data transfer/copy operations
  • Cross-Region operations
  • Retained backups
Important Principle

More storage and higher performance can increase cost.

Always remove unused resources when they are no longer required.

50. Most Important Interview Questions

Q1. What is EBS?
Answer: EBS (Elastic Block Store) is a cloud-based block storage service used primarily with EC2 instances.
Q2. What is EBS similar to?
Answer: It can be understood as a virtual hard drive for EC2.
Q3. Can an EC2 instance have multiple EBS volumes?
Answer: Yes, an EC2 instance can have multiple EBS volumes attached, subject to applicable limits and configuration.
Q4. Is EBS Region-specific or Availability Zone-specific?
Answer: An EBS volume is associated with a specific Availability Zone.
Q5. How can you use EBS data in another Availability Zone?
Answer: EBS → Snapshot → New EBS in target AZ
Q6. How can you move EBS data to another Region?
Answer: EBS → Snapshot → Copy Snapshot → Target Region → New EBS
Q7. What is an EBS Snapshot?
Answer: It is a point-in-time backup of an EBS volume.
Q8. Can you increase EBS volume size?
Answer: Yes. The transcript demonstrates modifying the volume to increase its size without restarting the EC2 instance for the volume modification.
Q9. What is Delete on Termination?
Answer: It determines whether an EBS volume is automatically deleted when its associated EC2 instance is terminated.
Q10. What is EBS Lifecycle Manager?
Answer: It helps automate snapshot creation, retention, copying and deletion according to policies.
Q11. What is the purpose of EBS encryption?
Answer: It provides encryption to protect EBS data and related storage operations.
Q12. What is the EBS Snapshot Recycle Bin?
Answer: It helps protect snapshots from accidental deletion by retaining deleted snapshots for a configured period.
