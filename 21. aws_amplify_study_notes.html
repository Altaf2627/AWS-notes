🚀 AWS Amplify — Detailed Notes

1. Introduction to AWS Amplify

AWS Amplify is a development platform that helps developers build, deploy, and host web and mobile applications using AWS services.

It simplifies many tasks that would otherwise require configuring multiple AWS services manually.

Amplify can help with:

  • Building & Deploying apps
  • Hosting websites
  • Continuous deployment
  • Custom domains & SSL/TLS
  • Authentication (Cognito)
  • APIs & Databases (DynamoDB)
  • Storage & Backend resources
  • Local development & Cloud Sandbox
Simple Definition

AWS Amplify simplifies the process of building, deploying, and hosting modern web and mobile applications on AWS.

3. AWS Amplify Pricing  |  4. Why Do We Need It?

Amplify provides a Free Tier for build, deployment, data storage, and backend-related resources. Always check current pricing docs!

Why Do We Need Amplify?

Creating a website is only one part of the process. Doing everything manually requires configuring several AWS services. Amplify simplifies this workflow:

Application→Deployment→Hosting→Custom Domain→SSL→HTTPS→Continuous Deployment

8 & 9 & 10. Build and Deployment Flow

After connecting GitHub, you select the repository and the branch. Give the app a name (e.g. My Static Website), then click Save and Deploy.

11. Automatic Deployment  |  12. Practical Example

One of the most useful features is continuous deployment.

Suppose the website is deployed. You edit index.html locally (e.g. changing text from V7 to V8) and push the commit to GitHub.

The Automation Flow

Git Commit (V8) ↓ Amplify detects change ↓ Build triggered ↓ Automatic Deploy ↓ Website displays V8
⭐ Key Concept Git commit → Amplify build → Automatic deployment → Updated website. You do not have to manually upload files again!

13. Deployment History

Amplify provides a clear view of deployment history. You can view: Deployment status, previous builds, commit information, and build details. This is vital for tracing when and why a deployment occurred.

14 & 15. Custom Domains and Route 53

A production website needs a custom domain (e.g. example.com) instead of the default Amplify URL. In Amplify, go to Hosting → Custom domains to add it.

If using Amazon Route 53:

User→Custom Domain→Route 53 DNS→Amplify→Website

Domain Registration vs DNS Management (16 - 19)

16. The Difference

Domain Registration: Buying/owning the domain name (example.com).

DNS Management: Managing where the domain actually points to (e.g. pointing it to Amplify).

17 & 18. Hosted Zone & NS

A Hosted Zone contains DNS info (A, CNAME records). The zone provides Name Servers (NS). You tell your registrar to use these Name Servers.

⭐ Key Point (19. External Providers)

A domain can be registered with one provider (e.g. Hostinger) while its DNS is managed through Route 53, provided the DNS delegation (Name Servers) is configured correctly.

20. SSL/TLS Certificate

When adding a custom domain, Amplify can configure an SSL/TLS certificate for HTTPS automatically.

Custom Domain→SSL Creation→Configuration→Activation→HTTPS Website

Local Development (36 - 42)

40. The Challenge

If the app runs locally on localhost:5173, how does it connect to AWS DynamoDB/Cognito?

The Solution: Amplify Output File

You download the Amplify output configuration file from the deployed AWS backend. This file tells your local React app exactly how to connect to the cloud resources.

Local App→Output Config→AWS Backend (DB/Auth)

50. Per-User Data  |  51. Authorization

If User A and User B use the app, they shouldn't see the same shared To-Do list.

User Login → User Identity → Authorization → Database Access → Only User's Data
⭐ Critical Interview Concept

Authentication: Who are you? (Login)

Authorization: What are you allowed to access? (User A accesses only A's data)

Cloud Sandbox (52 - 57)

What is it? An isolated cloud development environment for testing backend changes.

Why? You shouldn't modify the production/main backend while experimenting.

Command: npx ampx sandbox
Amplify Project | ┌───────┴───────┐ ↓ ↓ Main Sandbox Backend Backend (Real) (Test)

The Sandbox watches your local code for backend changes and updates the Sandbox cloud resources automatically.
