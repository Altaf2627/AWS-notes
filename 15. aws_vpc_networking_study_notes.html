AWS VPC & Networking
Detailed & Structured Study Notes

1. What is Amazon VPC?

VPC = Virtual Private Cloud

Amazon VPC is a logically isolated private network inside AWS where you can launch and control your AWS resources.

Why do we need a VPC?

To create a secure, isolated, and controlled network environment for your resources.

You control:

  • IP address ranges
  • Subnets & Routing
  • Internet connectivity
  • Network security
  • Access between resources

Major Benefits

  • Security — Isolate resources from unwanted access.
  • Control — You dictate routes and network rules.
  • Customization — Design network to fit app needs.
  • Isolation — Resources operate purely in your environment.
Important Note VPC is not unique to AWS. Other cloud providers have similar concepts (e.g., Azure calls it Virtual Network / VNet).

2. AWS Global Infrastructure

Before diving into VPC networking, understand these three terms: Region → Availability Zone → Resources

2.1 Region

A Region is a geographical area where AWS has infrastructure/data centers (e.g., Mumbai, London, Singapore, US East).

Why choose a nearby Region?
Generally, a geographically closer Region can help reduce network latency for your users. If your app serves Indian users, choose Mumbai.

3. Availability Zone (AZ)

An Availability Zone is an isolated location within an AWS Region. A Region contains multiple AZs.

AWS Region / | \ AZ-A AZ-B AZ-C | | | Server Server Server

Why multiple AZs?

To improve Availability, Fault tolerance, Resilience, and Disaster recovery.

If one AZ has a problem, resources in another AZ can continue operating.

⭐ Remember Region = Geographical area
AZ = Isolated location within a Region

4. VPC CIDR Block

When creating a VPC, you specify an IPv4 CIDR block.

CIDR = Classless Inter-Domain Routing. It is a notation used to define a range of IP addresses.

Example 1

10.0.0.0/16

10.0.0.0 → network address
/16 → prefix length

Total IPv4 addresses = 65,536

Math Formula

Total IPv4 = 2^(32 - prefix)

Example for /28:

2^(32-28) = 2^4 = 16 addresses

Important AWS Rule AWS reserves some IP addresses within each subnet for networking purposes (usually 5), so the number of addresses available for resources is lower than the mathematical total.

5. VPC Architecture

A basic AWS network visualization:

AWS Region │ └── VPC │ ├── Public Subnet │ └── EC2 / Application Server │ └── Private Subnet └── Database / Internal Resource

6. What is a Subnet?

A subnet is a smaller network segment created inside a VPC.

Suppose your VPC has a large IP range (10.0.0.0/16). You can divide it:

VPC: 10.0.0.0/16 ├── Public Subnet: 10.0.1.0/24 └── Private Subnet: 10.0.2.0/24

7. Resources Run Inside Subnets

Common Beginner Mistake:

"I'll create an EC2 instance directly inside the VPC."

Correct Flow:

VPC→Subnet→EC2 Instance
⭐ Remember

VPC = Large network

Subnet = Smaller network inside VPC

Resource = Runs inside a subnet

9. Subnets and Availability Zones

A subnet is tied to exactly one Availability Zone. However, you can create multiple subnets across different AZs.

Region: Mumbai │ ├── AZ-A │ └── Public Subnet ├── AZ-B │ └── Public Subnet └── AZ-C └── Private Subnet

Why? To improve availability and distribute workloads.

10. Route Table  |  11. Default Route

A Route Table contains rules that determine where network traffic should be sent.

It answers: "If traffic is going to this destination, where should it go?"

Public Subnet→Route Table→Internet Gateway

11. Default Route

0.0.0.0/0

Matches any IPv4 destination not matched by a more specific route.

Destination: 0.0.0.0/0 | Target: igw-xxx

12. Internet Gateway (IGW)

An IGW provides a path between a VPC and the internet.

Basic requirements for internet connectivity:

  • VPC & Subnet
  • Internet Gateway attached to the VPC
  • Route table with internet route pointing to IGW
  • Appropriate public IP addressing on the instance
  • Security rules allowing required traffic

13. Security Group  |  14. Characteristics

A Security Group is a virtual firewall that controls inbound and outbound traffic for supported resources like EC2.

Inbound vs Outbound

Inbound: What traffic can enter (e.g., HTTP : 80, SSH : 22).

Outbound: What traffic can leave.

14. Characteristics

  • Stateful: Allowed incoming traffic automatically allows the return response.
  • Allow Rules: They only support allow rules (no explicit deny).
  • Resource Level: Attached to instances/ENIs, not the whole subnet.

15. Network ACL (NACL)

NACL = Network Access Control List

A network-level firewall that controls traffic entering and leaving a subnet.

16. Security Group vs NACL

This is a highly tested interview/exam topic.

Feature Security Group (SG) Network ACL (NACL)
Level Resource / Network Interface Subnet level
Rules Allow only Allow + Deny
Stateful Yes (Return traffic auto-allowed) No (Stateless)
Applies to Explicitly associated resources Entire associated subnet
Common Use Protect individual resources Additional subnet-level filtering
Memory Trick SG → Security of the resource | NACL → Network/subnet access control

17. NACL Example

Subnet [ Protected by NACL ] │ ├── EC2-A ├── EC2-B └── EC2-C

If a NACL is attached to the subnet, its rules apply to all traffic entering or leaving the subnet, affecting all instances inside.

18. NAT Gateway

NAT = Network Address Translation

Allows resources in a private subnet to initiate connections to the internet, while preventing unsolicited inbound connections from the internet.

Example Use Case: Database in a private subnet needs to download patches or access external APIs.

19. NAT Gateway Architecture

Internet ▲ │ Internet Gateway ▲ │ NAT Gateway (in Public Subnet) ▲ │ Private Subnet (EC2)

Important: The private EC2 initiates outbound traffic via the NAT Gateway, but the internet cannot initiate an inbound connection to the private EC2.

20. VPC Peering

VPC Peering creates private network connectivity between two VPCs.

VPC-A (Mumbai)
← VPC Peering →
VPC-B (London)

Resources communicate using private IPs. Not a full mesh automatically (use Transit Gateway for many-to-many).

21. VPC Endpoint

Provides private connectivity from a VPC to supported AWS services (like S3) without using the public internet.

EC2→VPC Endpoint→AWS S3

Improves security and reduces internet dependency.

22. Bastion Host

A specially controlled server in a public subnet used as an entry point for accessing resources in private networks.

Internet → Bastion Host (Public) → Private EC2

Modern Alternative: AWS Systems Manager Session Manager often replaces bastions.

23. Elastic IP Address (EIP)

A static public IPv4 address. Normal EC2 public IPs can change on stop/start. Elastic IPs remain stable.

Best Practice Avoid allocating EIPs unnecessarily as they incur charges.

24. VPC Flow Logs

Captures information about IP traffic going to and from network interfaces in your VPC.

Use Cases: Troubleshooting connectivity, security investigation, network monitoring.

25. Direct Connect  |  26. Client VPN

25. Direct Connect

Dedicated, physical network connection from an on-premises data center directly to AWS (bypassing public internet).

Office/DC ↔ Dedicated Line ↔ AWS

26. Client VPN

Managed VPN service allowing users to securely connect to AWS networks remotely.

Remote User ↔ VPN ↔ AWS VPC

30 & 31. Public vs Private Concepts

What Makes it Public?

A subnet is public when its route table has a route (0.0.0.0/0) pointing to an Internet Gateway.

What Makes it Private?

It lacks a direct route to an Internet Gateway. It uses a NAT Gateway for outbound internet access.

32. Important: IGW vs NAT Gateway

Connects VPC to internetProvides outbound internet for private resources

Security Group

Architectural Examples (35 & 36)

35. Hosting a Website

Web server in Public Subnet (Security Group: allow HTTP 80 / HTTPS 443). Database in Private Subnet (Security Group: allow DB traffic ONLY from the Web server SG). This follows the principle of least exposure.

36. Private Server Needs Updates

Private EC2→NAT Gateway→Internet Gateway→Internet

Initiates outbound connection securely without allowing inbound internet access.

37. ⭐ Interview Questions

Q1. What is a VPC?
A logically isolated virtual network within AWS where you can launch and control resources.
Q2. What is a subnet?
A smaller IP/network segment mapped to an Availability Zone inside a VPC.
Q3. Difference between public and private subnet?
Public has a route to an IGW. Private does not provide direct inbound internet connectivity via an IGW.
Q4. What is an Internet Gateway?
It provides a path between a VPC and the internet for public-facing resources.
Q5. What is a Route Table?
Contains routing rules determining where network traffic should be forwarded.
Q6. What is a Security Group?
A stateful virtual firewall controlling inbound/outbound traffic at the resource/instance level.
Q7. What is a Network ACL?
A stateless firewall operating at the subnet level, supporting both allow and deny rules.
Q8. Security Group vs NACL?
SG: Resource level, stateful, allow rules only. NACL: Subnet level, stateless, allow & deny rules.

Q9. Why do we use a NAT Gateway?
To allow resources in private subnets to initiate outbound connections without exposing them to inbound internet traffic.
Q10. What is VPC Peering?
Private network connectivity between two specific VPCs.
Q11. What is a VPC Endpoint?
Private connectivity from a VPC to AWS services (like S3) without the internet.
Q12. What is a Bastion Host?
A controlled public server used as an entry point for administrative access to private resources.
Q14. What are VPC Flow Logs?
Logs that capture information about IP traffic to/from network interfaces in a VPC.
Q15. What is AWS Direct Connect?
Dedicated physical network connectivity between an on-premises data center and AWS.
