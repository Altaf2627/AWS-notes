1. Introduction to Web Servers

What is a Web Server?

A web server is software that receives requests from clients (usually web browsers) and sends back web content such as:

  • HTML
  • CSS
  • JavaScript
  • Images
  • Videos
  • Other static files

Communication generally happens using:

  • HTTP — Hypertext Transfer Protocol
  • HTTPS — HTTP Secure, which uses TLS encryption

Basic Working

┌─────────────────┐ │ Client/Browser │ └────────┬────────┘ │ │ HTTP Request │ Port 80 ▼ ┌─────────────────────┐ │ Apache Web Server │ │ (HTTPD) │ └──────────┬──────────┘ │ │ Fetches requested file ▼ ┌─────────────────────┐ │ Document Root │ │ /var/www/html │ └─────────────────────┘ │ ▼ HTTP Response HTML / CSS / JS

Example

When a user enters: http://example.com the browser sends a request to the web server.

Apache receives the request, finds the required content, and sends it back to the browser.

2. Local Hosting vs Production Hosting

Local File

If you open an HTML file directly from your computer:

file:///home/user/index.html

the browser is accessing the file directly from the local filesystem. This is not the same as hosting a website publicly.

Production Hosting

To make a website accessible through the Internet:

Internet↓Public IP / Domain↓Web Server↓Website Files

A server must:

  • Be connected to the Internet.
  • Have a reachable public IP or domain.
  • Run web-server software.
  • Listen on the required network ports.
  • Allow traffic through its firewall/security rules.

3. What is HTTPD?

HTTPD stands for HTTP Daemon.

  • HTTP → Hypertext Transfer Protocol
  • D → Daemon

A daemon is a background process that continuously runs and waits for incoming requests.
Apache is commonly referred to as: Apache HTTPD

Important Ports

ProtocolPortPurpose
HTTP80Normal web traffic
HTTPS443Encrypted web traffic
SSH22Remote server administration
Remember HTTP → 80  |  HTTPS → 443  |  SSH → 22

4. Apache in Production

Apache HTTPD can be used for several purposes.

4.1 Static Website Hosting

Apache can directly serve: HTML, CSS, JavaScript, Images, Fonts, Videos.

/var/www/html/index.html /var/www/html/styles.css /var/www/html/logo.png

4.2 Dynamic Web Applications

Apache can work with application runtimes such as: PHP, Python, Perl. This allows Apache to serve applications rather than only static files.

4.3 Reverse Proxy

Apache can receive requests from users and forward them to backend applications.

Client │ ▼ Apache │ ├──► Node.js Application │ ├──► Flask Application │ └──► Other Backend Services

Why use a reverse proxy? It can help with: Routing, Security, SSL/TLS termination, Backend abstraction, Centralized access control.

4.4 Load Balancing

Apache can distribute requests across multiple backend servers.

┌──► Server 1 │ Client ──► Apache │ ├──► Server 2 │ └──► Server 3

This can improve: Availability, Scalability, Fault tolerance, Performance.

4.5 Virtual Hosting

A single server can host multiple websites. Example: Server IP: 203.0.113.10

example1.com ──► Website 1 example2.com ──► Website 2 example3.com ──► Website 3

This is called Virtual Hosting.

4.6 Security & Encryption

Apache can also handle: SSL/TLS certificates, Access control, Authentication, Custom error pages, Security-related configuration.

7. Installing Apache HTTPD

On Amazon Linux/RHEL/Fedora-based systems, the Apache package is generally called: httpd

On Debian/Ubuntu systems, it is generally: apache2

Installation Commands

# Update installed packages sudo yum update -y # Install Apache sudo yum install httpd -y # Start Apache sudo systemctl start httpd # Enable Apache at boot sudo systemctl enable httpd # Check Apache status sudo systemctl status httpd

What Each Command Does

yum update
Updates available packages.
sudo yum update -y

yum install
Installs Apache.
sudo yum install httpd -y

systemctl start
Starts the Apache service immediately.
sudo systemctl start httpd

systemctl enable
Makes Apache start automatically after reboot.
sudo systemctl enable httpd

systemctl status
Shows the current service state.
sudo systemctl status httpd

8. Linux Firewall Configuration

When running Apache on a local RHEL/CentOS-type server, the operating-system firewall may also need to allow HTTP and HTTPS.

Using firewalld:

sudo firewall-cmd --permanent --add-service=http sudo firewall-cmd --permanent --add-service=https sudo firewall-cmd --reload
Important

On AWS, there can be multiple network-control layers, including:

Browser→AWS Security Group→OS Firewall→Apache→Website

Therefore, opening a port in only one place may not be sufficient.

10. Document Root

What is Document Root?

The Document Root is the directory from which Apache serves website files.

On Amazon Linux/RHEL-based Apache installations, a common default is:

/var/www/html

Example

/var/www/html │ ├── index.html ├── styles.css ├── images/ └── scripts/

When a browser requests: http://example.com/index.html
Apache can map that URL to: /var/www/html/index.html

11. Creating a Custom Website

Navigate to the Document Root: cd /var/www/html

Create an HTML file: sudo vi index.html

Example HTML

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>Production Web Server</title> <link rel="stylesheet" href="styles.css"> </head> <body> <h1>Welcome to Our Production Web Server</h1> <p>This page is served by Apache.</p> </body> </html>

Create CSS: sudo vi styles.css

body { font-family: Arial, sans-serif; background-color: #f4f4f4; text-align: center; padding-top: 50px; } h1 { color: #0056b3; }

Now refresh: http://<EC2_PUBLIC_IP>. Your custom webpage should appear.

12. Apache Configuration File

The main Apache configuration file on RHEL/Amazon Linux-style installations is:

/etc/httpd/conf/httpd.conf

This file controls important Apache behavior.

Important Apache Directives

DirectivePurpose
ServerRootDefines Apache's main configuration/module directory
ListenSpecifies the port/IP Apache listens on
IncludeOptionalLoads additional configuration files
UserDefines the user running Apache processes
GroupDefines the group running Apache processes
DocumentRootDefines the website's root directory
DirectoryIndexDefines the default file served for a directory
ErrorLogDefines the error log

Example

ServerRoot "/etc/httpd" Listen 80 DocumentRoot "/var/www/html" DirectoryIndex index.html ErrorLog "logs/error_log" CustomLog "logs/access_log" combined

13. Understanding Important Directives

Listen
Listen 80
Tells Apache to listen for HTTP requests on port 80. For HTTPS: Listen 443

DocumentRoot
DocumentRoot "/var/www/html"
Specifies where website files are stored.

DirectoryIndex
DirectoryIndex index.html
When a user visits http://example.com/, Apache can automatically look for index.html.

ErrorLog & CustomLog
ErrorLog "logs/error_log" stores errors/warnings.
CustomLog "logs/access_log" combined records incoming client requests.

14. Apache Configuration Includes

Apache supports modular configuration. For example:

IncludeOptional conf.d/*.conf

This means Apache can load additional .conf files from: /etc/httpd/conf.d/
This is useful because configurations can be separated into smaller files rather than putting everything into one large file.

15. Apache Directory Security

Apache controls access to filesystem directories using <Directory> blocks. Example:

<Directory /> AllowOverride none Require all denied </Directory>

This prevents general web access to the server's root filesystem. Then:

<Directory "/var/www/html"> Options Indexes FollowSymLinks AllowOverride None Require all granted </Directory>

allows access to the website's Document Root.

Security Principle

Operating System↓Deny by default↓Website directory↓Explicitly allow access

This is safer than allowing access to the entire filesystem.

16. MIME Types

Browsers need to know what type of content they are receiving. Apache uses MIME type mappings to associate file extensions with media types.

21. Domain Name  |  22. What is DNS?

A public IP address works, but users generally prefer a domain name. Instead of http://203.0.113.10 we want http://myexamplewebsite.xyz.

DNS = Domain Name System. DNS translates domain names into IP addresses.

myexamplewebsite.xyz │ ▼ DNS (A Record) │ ▼ EC2 Public IP │ ▼ Apache Web Server

23. DNS A Record  |  24. DNS Configuration Steps

An A record maps a domain name to an IPv4 address.

Example Records

HostTypeValue
@AEC2 Public IP
wwwAEC2 Public IP

@ generally represents the root/apex domain (myexamplewebsite.xyz).

Configuration Steps

  1. Open DNS Management (GoDaddy, Route 53, etc.)
  2. Create A Record for root (@) to IP.
  3. Create A Record for www to IP.
  4. Verify DNS using: dig +short myexamplewebsite.xyz

25. DNS Propagation

DNS changes may not become visible everywhere immediately. Propagation time varies by TTL, caching, and resolvers. Don't assume a DNS change is broken simply because it doesn't appear instantly.

26. HTTPS & SSL/TLS

HTTP traffic can be observed or modified more easily than properly encrypted HTTPS traffic. HTTPS uses TLS (Transport Layer Security) to provide: Encryption, Integrity, and Server authentication.

HTTP

Browser ──► Server

Unencrypted traffic (Port 80)

HTTPS

Browser ══► Server

Encrypted TLS connection (Port 443)

Let's Encrypt & Certbot (27 - 30)

Let's Encrypt provides publicly trusted TLS certificates.
Certbot is a tool that obtains/manages certificates using the ACME protocol.

28. Install: sudo yum install certbot python3-certbot-apache -y

29. Obtain Certificate: Standalone mode temporarily uses port 80. Stop Apache first!

sudo systemctl stop httpd
sudo certbot certonly --standalone -d myexamplewebsite.xyz

30. Certificate Files

Stored in: /etc/letsencrypt/live/...

  • fullchain.pem → Public cert chain
  • privkey.pem → Private key (Secret!)

⚠️ Never expose or share the private key.

31. Configuring HTTPS in Apache

Apache can be configured to listen on port 443.

Listen 443 <VirtualHost *:443> ServerName myexamplewebsite.xyz DocumentRoot /var/www/html SSLEngine on SSLCertificateFile /etc/letsencrypt/live/myexamplewebsite.xyz/fullchain.pem SSLCertificateKeyFile /etc/letsencrypt/live/myexamplewebsite.xyz/privkey.pem ErrorLog /var/log/httpd/ssl_error_log CustomLog /var/log/httpd/ssl_access_log combined </VirtualHost>

32. Understanding <VirtualHost>

A VirtualHost defines how Apache should handle requests for a particular host/domain.

<VirtualHost *:443>
ServerName myexamplewebsite.xyz
</VirtualHost>

Meaning: Handle HTTPS requests for myexamplewebsite.xyz on port 443. This becomes especially useful when hosting multiple domains on one server.

33. Validate Apache Config  |  34. Reload vs Restart

Before restarting/reloading, check syntax:

sudo httpd -t

Expected result: Syntax OK

Why? A mistake can prevent Apache from starting.

Restart:

Stops and starts the service. (systemctl restart)

Reload:

Reloads config while keeping service running. (systemctl reload)

Custom 404 Error Page (36 - 39)

404 Not Found means the requested resource could not be found. Apache returns a default page, but you can customize it.

Step 1: Create the HTML page:

sudo vi /var/www/html/error_404.html

Step 2: Configure httpd.conf:

ErrorDocument 404 /error_404.html

Step 3: Apply

httpd -t→reload→test bad URL

Apache will now serve the custom HTML file instead of the default error message.

1. Virtual Hosts (VHosts)

Virtual Hosting allows a single Apache HTTPD server to host multiple websites/domains.

Each website can have its own: Domain name, Document Root, Log files, SSL/TLS config, Security rules, Application backend.

Virtual Host Architecture

Incoming Web Requests │ ┌─────────────┴─────────────┐ ▼ ▼ Host: site1.xyz:443 Host: site2.com:80 │ │ ▼ ▼ /var/www/site1.xyz/ /var/www/site2.com/ HTTPS/TLS HTTP

2. Separate Directories  |  3. Modular Config

Instead of putting everything in /var/www/html/, create independent directories:

sudo mkdir -p /var/www/site1.xyz
sudo mkdir -p /var/www/site2.com

Why? Better organization, security isolation, deployment mgmt, and troubleshooting.

Modular Configuration

Instead of one huge httpd.conf, use separate files in /etc/httpd/conf.d/ (e.g., site1.conf, site2.conf). Loaded via IncludeOptional conf.d/*.conf.

4. HTTPS Virtual Host  |  5. HTTP Virtual Host

# /etc/httpd/conf.d/site1.conf Listen 443 <VirtualHost *:443> ServerName myexamplewebsite.xyz ServerAlias www.myexamplewebsite.xyz DocumentRoot /var/www/site1.xyz SSLEngine on SSLCertificateFile /etc/.../fullchain.pem SSLCertificateKeyFile /etc/.../privkey.pem ErrorLog /var/log/httpd/site1_error.log CustomLog /var/log/httpd/site1_access.log combined </VirtualHost>
# /etc/httpd/conf.d/site2.conf Listen 80 <VirtualHost *:80> ServerName mywebsite2.com ServerAlias www.mywebsite2.com DocumentRoot /var/www/site2.com ErrorLog /var/log/httpd/site2_error.log CustomLog /var/log/httpd/site2_access.log combined </VirtualHost>

7. Reverse Proxy

A reverse proxy is a server that receives requests from clients and forwards those requests to an internal backend server.

Internet→Apache (ProxyPass)→127.0.0.1:3000→Node.js App
SYSTEM ADMINISTRATION & DEVOPS // STUDY NOTES PAGE 15

8. Why Use a Reverse Proxy?

  • Security: Backend app listens only on 127.0.0.1. Not exposed publicly.
  • Clean URLs: Users see https://app.example.com instead of http://example.com:3000.
  • SSL/TLS Termination: Apache handles the HTTPS cert, app just uses HTTP over localhost.

9. Node.js Setup

sudo yum install nodejs -y
npx create-react-app app
npm run build
npx serve -s build -l 3000

Test: curl -I http://127.0.0.1:3000

10. Apache Reverse Proxy Config  |  11. Directives

<VirtualHost *:80> ServerName app.myexamplewebsite.xyz ProxyPreserveHost On ProxyPass / http://127.0.0.1:3000/ ProxyPassReverse / http://127.0.0.1:3000/ ErrorLog /var/log/httpd/react_proxy_error.log CustomLog /var/log/httpd/react_proxy_access.log combined </VirtualHost>
DirectiveMeaning
ProxyPreserveHostPreserves original Host header when forwarding.
ProxyPassForwards requests received at / to the backend.
ProxyPassReverseRewrites backend redirect headers so client uses public URL.

12. Complete Flow

Public Internet→https://app...→Apache→127.0.0.1:3000→Node.js

The client knows about app.example.com but not 127.0.0.1:3000.

Layer 7 Load Balancing (13 - 15)

Load balancing distributes incoming client requests across multiple backend servers using modules like mod_proxy_balancer.

Why Load Balance?

  • Scalability: Add more servers
  • Availability: Survive server failures
  • Performance: Distribute the load
  • Maintenance: Take nodes offline safely
Client Traffic │ ▼ Apache Load Balancer │ ┌───────┴───────┐ ▼ ▼ Node 1 Node 2 10.0.1.10 10.0.1.20

16. Apache LB Config  |  17. Directives

<VirtualHost *:80> ServerName cluster.myexamplewebsite.xyz <Proxy "balancer://production_cluster"> BalancerMember http://10.0.1.10:80 BalancerMember http://10.0.1.20:80 ProxySet lbmethod=byrequests </Proxy> ProxyPass / balancer://production_cluster/ ProxyPassReverse / balancer://production_cluster/ </VirtualHost>

<Proxy>: Defines logical backend cluster.
BalancerMember: Defines backend servers.
ProxySet lbmethod: Load-balancing strategy.

18. Load Balancing Methods

MethodValueIdea
Request-basedbyrequestsDistributes requests among workers
Traffic-basedbytrafficConsiders transferred traffic size
Busy-basedbybusynessConsiders active worker connections
HeartbeatheartbeatUses health/heartbeat information

20. Production Hardening  |  21. HTTP Basic Auth

Hardening improves Security, Reliability, Performance, Monitoring, and Access control.

Basic Authentication

Protect restricted areas like /admin.

Step 1: Create Password File

sudo htpasswd -c /etc/httpd/.htpasswd adminuser

Step 2: Protect Directory in Config

<Directory "/var/www/site1.xyz/admin"> AuthType Basic AuthName "Restricted Administration Portal" AuthUserFile /etc/httpd/.htpasswd Require valid-user </Directory>

Security Note: Always use over HTTPS!

22. Connection Timeouts

Timeout settings control how long Apache waits for operations.

Global Timeout

Timeout 60

Proxy Timeout

ProxyTimeout 15

Why important? Prevents resources from being tied up indefinitely by slow clients, unresponsive backends, or network problems.

23. Response Caching  |  24. Benefits

Caching reuses previously generated responses (via mod_cache, mod_cache_disk).

  • Reduce backend requests
  • Improve response times
  • Reduce server workload
  • Improve scalability

Be Careful: Do not blindly cache sensitive/user-specific responses (e.g., auth, shopping cart).

32. Important Production Best Practices

  • Keep backend private: 127.0.0.1 or private IP. Don't expose :3000 publicly.
  • Use HTTPS: TLS everywhere for prod.
  • Protect Admin endpoints: Use Auth for /admin.
  • Monitor Logs: access_log and error_log.
  • Validate config: sudo httpd -t before reload.
  • Least Privilege: Only needed permissions.
  • Protect Private Keys: NEVER expose privkey.pem.
