1. What is Docker?

Docker is a containerization platform/tool used to create, manage, package, and run applications inside containers.

It is especially useful for developers because it simplifies the complete application lifecycle, including:

  • Application development
  • Packaging
  • Testing
  • Shipping
  • Deployment
  • Running applications

Docker is very popular because it allows applications to run in an isolated and consistent environment.

Simple Definition

Docker packages an application together with the dependencies and configuration it needs so that it can run consistently in different environments.

2. Why Do We Need Docker?

One of the most common problems in software development is:

“It works on my machine, but it doesn't work on yours.”

Example

Suppose a developer creates an application. The application depends on: Node.js, Python, Database, Libraries, Dependencies, Configuration files, Environment variables, External services, and Specific software versions.

The developer successfully runs the application on their computer. Everything works perfectly. Now the testing team receives the application and tries to run it. But the application does not work.

The developer says: “The application is working fine on my machine.”

Why does this happen?

Because the developer's and tester's environments may be different. For example:

Developer EnvironmentTester Environment
Node.js v14Node.js v16
Required library installedLibrary missing
Correct configurationDifferent configuration
Required environment variablesMissing variables
Required dependency versionDifferent dependency version
Required service versionDifferent service version

These differences can create compatibility issues.

3. Docker as a Solution

Docker solves this problem by allowing the developer to package the application together with everything required to run it.

The package can contain: Application code, Dependencies, Libraries, Required tools, Configuration, Required runtime, Other necessary components.

The developer can then provide this package to the testing team. The tester only needs a Docker environment to run the package.

4. What is a Container?

A container is an isolated environment in which an application runs together with the dependencies it needs.

Think about a real-world shipping container. A shipping container: Holds goods, Keeps them together, Makes transportation easier, Can be moved from one place to another, Is isolated from other containers.

Docker containers work on a similar concept. A Docker container packages an application and the components required to run it.

5. Real-Life Container Analogy

Imagine that you need to transport something that must remain in a very cold environment.

Required item + Temperature control + Facilities

The container maintains the required environment while the item is transported. Similarly, a Docker container provides an isolated environment for an application.

Multiple Containers

You can have multiple containers on the same system:

+-------------------+ +-------------------+ +-------------------+ | Container 1 | | Container 2 | | Container 3 | | Application A | | Application B | | Application C | +-------------------+ +-------------------+ +-------------------+

Each container provides isolation for its application.

6. Definition of Container

A container can be understood as:

A lightweight, isolated runtime environment that packages an application together with the dependencies and configuration required to run it.

Benefits of Containers:

  • Isolation
  • Portability
  • Consistency
  • Easy deployment
  • Easy sharing
  • Efficient resource usage
  • Faster application delivery

8. How Containers Reduce Compatibility Problems

Suppose an application requires: Application + Node.js 14 + Libraries + Dependencies + Configuration.

All of these requirements can be packaged into a Docker image and used to create a container. Therefore, when the application is moved to another environment, the required components travel with it.

Without Docker

Application↓Different Environment↓Compatibility Problems↓Application may fail

With Docker

App + Dependencies + Config↓Docker Image↓Container↓Run Application

9. Running Multiple Versions on the Same Machine

Another important benefit of containers is that multiple versions of software can be used independently.

Example

Suppose one application requires: Node.js 14 and another application requires: Node.js 16. Without isolation, managing different versions can become difficult. With Docker:

Machine │ ├── Container 1 │ ├── Application 1 │ └── Node.js 14 │ └── Container 2 ├── Application 2 └── Node.js 16

The applications can run in separate containers with their required environments.

⭐ Important Containers provide isolation, so applications can have different dependencies or runtime versions without directly interfering with each other.

10. Docker vs Virtual Machines

Docker containers and Virtual Machines (VMs) both provide isolation, but they work differently.

Docker Containers

Containers generally share the host operating system's kernel and isolate application processes. They package: Application, Dependencies, Required runtime/environment. They do not generally package a complete guest operating system for every application.

Virtual Machines

A VM virtualizes a complete machine and normally includes: Virtual hardware, Guest operating system, Libraries, Applications.

Simplified Comparison

Virtual Machines Hardware ↓ Host OS ↓ Hypervisor ↓ +-------------+ +-------------+ | VM 1 | | VM 2 | | Guest OS | | Guest OS | | Application | | Application | +-------------+ +-------------+
Docker Hardware ↓ Operating System ↓ Docker Engine ↓ +-----------+ +-----------+ +-----------+ |Container 1| |Container 2| |Container 3| |Application| |Application| |Application| +-----------+ +-----------+ +-----------+

Key Differences

12. What is a Dockerfile?

A Dockerfile is a text file containing instructions used to build a Docker image. It describes things such as: Base image, Working directory, Files to copy, Dependencies to install, Ports to expose, Commands to execute, Application startup command.

Example Dockerfile

FROM node:20 WORKDIR /app COPY package*.json ./ RUN npm install COPY . . EXPOSE 3000 CMD ["npm", "start"]

Explanation

FROM: Specifies the base image (e.g. Node.js environment).

WORKDIR: Sets the working directory.

COPY: Copies files from the project into the image.

RUN: Executes a command while building the image.

EXPOSE: Documents the port the app uses.

CMD: Default command to run when container starts.

13. Docker Image  |  14. Image vs Container

A Docker image is a packaged, immutable template containing the application and the components required to create and run a container. It can contain: Application code, Runtime, Libraries, Dependencies, Configuration required by the image, Other required files.

Dockerfile→docker build→Docker Image

14. Image vs Container (Very Important)

Docker Image

An image is a template/package.

Docker Container

A container is a running instance of an image.

Docker Image │ ├──── Run → Container 1 │ ├──── Run → Container 2 │ └──── Run → Container 3
Easy Analogy Image = Blueprint | Container = Actual running building created from that blueprint

15. Docker Registry  |  16. Docker Hub

15. Docker Registry

A Docker Registry is a storage and distribution system for Docker images. It allows images to be: Stored, Shared, Uploaded, Downloaded, Distributed. There can be public registries and private registries.

Developer→Build→Push→Registry→Pull→Another Dev/Server

16. Docker Hub

Docker Hub is a popular public Docker registry provided by Docker. It contains many publicly available container images. (e.g. Node.js, Python, MongoDB, Nginx, Redis, Ubuntu, MySQL).

Instead of creating from scratch:

docker pull node

This downloads a Node image from a registry such as Docker Hub.

17. Public vs Private  |  18. Registry vs Repository

17. Public vs Private Registries

Public Registry: Images are available publicly, subject to access rules (e.g. Docker Hub). Useful for sharing with the wider community.

Private Registry: Used to store images that should not be publicly accessible (e.g. Proprietary applications, Internal services, Private code).

18. Registry vs Repository

Registry: The larger image storage/distribution service (e.g. Docker Hub).

Repository: A collection of related images, commonly organized around an image/app name and its versions or tags.

Docker Hub (Registry) │ ├── node (Repository) │ ├── node:18 │ └── node:20 │ └── nginx (Repository) └── nginx:latest

Registry = Library | Repo = Section | Tag = Edition

19. Important Docker Commands

19.1 docker pull
Used to download an image from a registry. docker pull node:20

19.2 docker run
Used to create and start a container from an image. docker run node

19.3 docker build
Used to build an image from a Dockerfile. docker build -t my-image .
(-t names the image, . uses current directory)

19.4 docker ps
Shows running containers. docker ps (Add -a to see stopped ones too).

19.5 docker stop
Stops a running container. docker stop my-container

19.6 docker images
Lists Docker images available locally. docker images
