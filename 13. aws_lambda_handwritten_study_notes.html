AWS Lambda — Detailed & Structured Notes

1. What is AWS Lambda?

AWS Lambda is a managed serverless compute service provided by AWS.

It allows you to run your code in the cloud without managing the underlying servers yourself.

Normally

If you want to execute some code, you need a machine/server.

Laptop / EC2 Instance↓Run Code

With Lambda

Your Code↓AWS Lambda↓AWS manages infra

You mainly provide the code, while AWS handles the underlying compute infrastructure.

2. What Does "Serverless" Mean?

A common misunderstanding is: "Serverless means there are no servers." That is not literally true.

Servers are still required to execute your code. Serverless means that AWS manages the servers and infrastructure for you.

You don't have to manually manage: Server provisioning, Operating system, Hardware, Server maintenance, Infrastructure scaling.

Simple Definition Serverless = You focus on code; AWS manages the underlying infrastructure.

3. Why Use AWS Lambda?  |  4. Main Features

With traditional servers (like EC2), you manage CPU, Memory, Storage, OS, Scaling, and Maintenance.

This makes Lambda particularly useful for small, event-driven tasks.

Main Features of AWS Lambda

  • 1. No Server Management: AWS manages the infrastructure required to execute your functions.
  • 2. Upload Your Code: You can deploy your function code directly to Lambda.
  • 3. Automatic Scaling: Lambda can create multiple concurrent function executions when many events arrive.
  • 4. Event-Driven Execution: A Lambda function normally runs when it is invoked by an event or request.
  • 5. Pay for Usage: Usage-based pricing model. You generally pay according to execution/request usage.
  • 6. Suitable for Short Tasks: Designed for relatively short-lived workloads rather than continuously running applications.

8. Lambda Handler  |  9. Testing a Function

8. Lambda Handler

The main entry point for execution. The handler receives information about the event and executes the required logic.

Event↓Lambda Handler↓Your Code↓Response

9. Testing a Lambda Function

A Lambda function does not simply execute continuously. You can manually invoke it using the Test feature.

Function→Create Test Event→Invoke→View Response

10. What is an Event?  |  11. Example Function

An event contains information that is passed to a Lambda function when it is invoked. { "message": "Hello" }

Important Concept Creating a function does not automatically mean that the code is constantly running. It executes when invoked.

11. Example Python Function

import json def lambda_handler(event, context): print("Hello from Lambda") return { "statusCode": 200, "body": json.dumps("Hello") }
  • event → information about the invocation
  • context → information about the Lambda execution environment
  • lambda_handler → handler function
  • return → response returned by the function

Lambda Permissions & IAM Roles (25 - 29)

Permissions are very important when Lambda interacts with other AWS services.

26. Execution Role

An IAM role that determines what AWS resources the function is allowed to access.

What can the Lambda access?

Lambda → Execution Role → S3 Read Perm → S3 Bucket

28. Resource-Based Policies

Controls which AWS services or principals are allowed to invoke the Lambda function.

Who can invoke the Lambda?

S3 → Invoke Permission → Lambda Function
29. S3 to Lambda Permission Flow

S3 needs permission to invoke Lambda (Resource-based).

Lambda needs permission to access other resources (Execution Role).

30. AWS Lambda Limitations

Lambda is powerful, but not suitable for every workload.

30.1 Execution Time Limit

Lambda functions are designed for short-lived tasks. The maximum execution time is 15 minutes.

Short Task → Lambda
Long-Running App → EC2 / ECS

31. Hosting  |  32. Stateless Nature

31. Not an always-running server: Lambda is not designed to host an entire traditional website (24/7 continuous server). Combine with API Gateway + DB for a serverless backend.

32. Stateless Nature

Functions are treated as stateless. Do not depend on in-memory info from a previous invocation.

Use external services for persistent state: DynamoDB, S3, RDS.

33. Cold Start  |  34. Warm vs Cold Execution

If a function hasn't been invoked recently, an initialization delay can occur. This is a Cold Start.

Cold Start

Request ↓ Initialize environment ↓ Run function

Warm Execution

Request ↓ Existing environment ↓ Run function

Use Cases (35 - 39)

Lambda is excellent for short, event-driven, automatically scalable tasks.

  • 1. Image Processing: User uploads image to S3 → Lambda resizes, compresses, generates thumbnails.
  • 2. Data Processing: Data enters DB → Lambda validates, cleans, transforms.
  • 3. Real-Time Notifications: User signs up → Event fires → Lambda sends welcome email.
  • 4. API Backend: Combined with API Gateway to create serverless backends connecting to databases.

40. Automatic Scaling

Lambda can automatically scale the number of concurrent executions according to incoming demand.

Requests │ ┌─────────────┼─────────────┐ ▼ ▼ ▼ Lambda Lambda Lambda Execution Execution Execution #1 #2 #3

41. Why it's useful: If 100 users sign up simultaneously, instead of manually creating 100 servers, Lambda creates concurrent execution environments as needed.

42. Pay-As-You-Go  |  43. Lambda vs EC2

42. Pricing: Usage-based model. You pay for executions, not continuous server uptime.

44. Vs Containers: Containers host long-running processes. Lambda executes a function and completes.

52. Important Concepts

  • Serverless: AWS manages servers.
  • Function: Unit of code executed.
  • Event: Input that causes execution.
  • Trigger: Mechanism invoking Lambda.
  • Handler: Function entry point.
  • Execution Role: IAM permissions.
  • CloudWatch: Monitoring & logs.
  • Cold Start: Init delay.
  • Stateless: No persistent local memory.

53. Advantages

  • No server management
  • Automatic scaling
  • Event-driven workflow
  • Usage-based pricing
  • Fast development & Integration

54 & 55. Limitations

  • 15-minute max duration
  • Stateless design
  • Cold starts
  • Not for continuous workloads
