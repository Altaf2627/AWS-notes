Terraform — Infrastructure as Code (IaC)

1. Introduction to Terraform

Terraform is an open-source Infrastructure as Code (IaC) tool developed by HashiCorp.

What is Infrastructure as Code?

Infrastructure as Code means using code and configuration files to create, manage, modify, and delete cloud infrastructure.

Instead of manually creating resources through a cloud provider's console, you define the desired infrastructure in a configuration file and let Terraform handle the infrastructure creation process.

Manual Example

AWS Console↓EC2 Dashboard↓Launch Instance↓Select AMI↓Select Instance Type↓Configure Settings↓Launch

Terraform Example

Terraform Configuration↓Terraform Commands↓Cloud Provider↓EC2 Instance Created

Terraform allows you to define the desired EC2 infrastructure in code.

2. Multi-Cloud Support

One of Terraform's major advantages is that it supports multiple cloud providers and infrastructure providers.

Examples mentioned in the course include:

AWS Google Cloud Platform (GCP) Microsoft Azure

Therefore, Terraform can act as a common IaC tool across different cloud platforms.

Key Point Terraform is not limited to a single cloud provider. This makes it useful when organizations work with multiple cloud environments.

3. Configuration Files  |  4. HCL

3. Configuration Files

Terraform configuration files generally use the .tf file extension.

Provider ↓ Region / Location ↓ Resource Type ↓ Resource Configuration

4. HCL (HashiCorp Configuration Language)

Terraform configurations are written using HCL. It is designed to make infrastructure configuration relatively easy to read and write.

Terraform↓HCL↓.tf files

5. Declarative Approach

Terraform follows a declarative approach.

What does declarative mean?

You specify the desired result, rather than manually specifying every step required to achieve that result.

For example:

"I want an AWS EC2 instance using this AMI and this instance type."

Terraform determines the necessary actions to create that infrastructure.

Imperative Approach

Step 1 → Do this Step 2 → Do this Step 3 → Do this Step 4 → Do this

Declarative Approach

Desired State↓Terraform determines required actions↓Infrastructure
Key Point You describe WHAT you want; Terraform handles HOW to achieve it.

6. Basic Terraform Workflow

Terraform's basic workflow can be remembered using three main stages:

Configuration→init→plan→apply→Infrastructure Ready

For cleanup: terraform destroy

7 - 9. Core Commands

7. terraform init

The first command generally used in a Terraform project. It initializes the Terraform working directory and prepares the project for Terraform operations.

8. terraform plan

Shows the changes Terraform intends to make. It allows you to review the proposed infrastructure changes before actually applying them. Helps you understand what will be created, modified, or removed.

9. terraform apply

Applies the Terraform configuration and creates or modifies the required infrastructure.

terraform apply→Review→Confirm (yes)→Resources Created/Modified

10. Example — Creating an EC2 Instance

Suppose the Terraform configuration defines an AWS EC2 instance. The workflow is:

.tf Configuration File ↓ terraform init ↓ terraform plan ↓ Review Changes ↓ terraform apply ↓ EC2 Instance Created

11. Modifying Infrastructure

Terraform is not only used to create resources. It can also modify existing infrastructure.

Example

Suppose your EC2 instance initially has the tag: Name = My Server. You change it in your Terraform configuration to: Name = My Web Server.

Modify .tf File→terraform apply→Terraform Detects Change→Resource Modified

Terraform identifies the required modification and updates the resource. The EC2 instance can remain running while the applicable property is changed.

12. terraform destroy

After testing or when the infrastructure is no longer required, you can remove resources using: terraform destroy

Terraform shows what it intends to destroy and asks for confirmation.

terraform destroy ↓ Review Resources ↓ Confirm ↓ Resources Destroyed

Important Use Case

This is particularly useful for temporary environments such as:

  • Testing
  • Development
  • Experiments
  • Training environments

Terraform's Major Benefits (13 - 16)

13. Consistency

Terraform allows infrastructure to be defined in configuration files. The same configuration can be reused multiple times.

Same Configuration ↓ Environment 1 Environment 2 Environment 3

14. Automation

Terraform is command-based, which makes it suitable for automation and scripting.

Script→Terraform→Cloud Provider

15. Cost Saving

Terraform can help with cost control when infrastructure is temporary.

Create Infra→Use→Destroy Infra

Note: Terraform itself does not automatically guarantee cost savings. It depends on your automation.

16. Repeatable Infrastructure

Terraform makes it easier to reproduce an environment.

Testing Configuration ↓ Reusable Terraform Code ↓ Production-like Environment

Reduces the need to manually recreate infrastructure.

17. Terraform State Management

One of Terraform's important concepts is state management. Terraform maintains information about the infrastructure it manages in a state file.

A commonly used local state file is: terraform.tfstate

Why is state important?

Terraform uses state information to understand the relationship between Terraform Configuration and Managed Resources.

18. Example of State Management

Suppose Terraform created an EC2 Instance with Name = My Server. Later you change the configuration to Name = My Web Server.

Terraform Configuration ↓ State ↓ Actual Infrastructure ↓ Determine Difference ↓ Apply Required Change

19. Local and Remote State

State can initially be maintained locally. However, Terraform also supports remote state storage.

This becomes particularly useful when Terraform is used by teams or in shared environments.

Local State OR Remote State

Terraform Features (20 - 22)

20. Variables

Variables allow configurations to become more flexible and reusable. Instead of hard-coding every value, you can define values separately.

Variable→Configuration→Different Values

21. Functions

Terraform provides functions that can be used to process and manipulate values within configurations. Functions help make configurations more dynamic.

22. Loops in Terraform

Terraform supports concepts that allow you to work with multiple similar resources. For example, if you need to create multiple user accounts, iteration features reduce repetitive configuration.

23. Terraform Modules  |  24. Benefits

A Terraform module is a reusable collection of Terraform configuration.

Why use modules?

Suppose you create a complete configuration for a particular infrastructure component. Instead of copying the same code into multiple projects, you can package it as a module and reuse it.

Terraform Code ↓ Module ↓ Reuse in Multiple Projects

24. Benefits of Modules

  • Reusability
  • Better organization
  • Less code duplication
  • Easier maintenance
  • Standardized infrastructure
Key Idea: Write once → Package as a module → Reuse wherever required.

25. Terraform Workspaces

Workspaces can be used when you want to work with separate Terraform states for different environments while using the same basic configuration.

Terraform Configuration │ ├── Dev Workspace ├── Test Workspace └── Production Workspace

26. Terraform Cloud

Terraform Cloud is a managed service from HashiCorp that can make Terraform workflows easier to manage.

Local Setup

Developer↓Local Terraform↓Local Configuration↓Local State

Terraform Cloud

Developer / Team↓Terraform Cloud↓Terraform Operations↓Cloud Infrastructure

27. Terraform and Version Control

Terraform configuration files can be stored in version-control systems such as Git repositories.

.tf Files→Git Repository→Team Collaboration

This provides benefits such as: Version history, Collaboration, Change tracking, Review of infrastructure changes.

🎯 Interview-Friendly Questions

Q1. What is Terraform?
Terraform is an open-source Infrastructure as Code tool developed by HashiCorp. It allows infrastructure to be defined, created, modified, and managed using configuration files.
Q2. What is IaC?
IaC stands for Infrastructure as Code. It means managing infrastructure through code/configuration rather than manually creating resources through a cloud console.
Q3. What language does Terraform use?
Terraform primarily uses HashiCorp Configuration Language (HCL).
Q4. What is the Terraform file extension?
Terraform configuration files commonly use the .tf extension.
Q5. What is terraform plan?
It previews the changes Terraform intends to make before those changes are applied.
Q6. What is terraform apply?
It applies the Terraform configuration and creates or modifies the required infrastructure.
Q7. What is terraform destroy?
It destroys infrastructure managed by the Terraform configuration.
Q8. What is Terraform state?
Terraform state contains information Terraform uses to track and manage infrastructure resources.
Q9. What are Terraform modules?
Modules are reusable collections of Terraform configuration that help organize and standardize infrastructure code.
Q10. Why is Terraform useful?
Terraform provides automation, consistency, repeatability, reusable infrastructure definitions, state management, and support for multiple infrastructure providers.
