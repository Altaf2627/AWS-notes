AWS VPC — Practical Setup & Networking Notes

1. Creating a VPC

What is a VPC?

A Virtual Private Cloud (VPC) is an isolated virtual network in AWS where you can launch resources such as EC2 instances.

When creating a VPC, the important configuration is the CIDR block.

Example

VPC Name: my-vpc

IPv4 CIDR: 10.0.0.0/16

IPv6: Not required for this example

A /16 IPv4 CIDR represents 65,536 total IPv4 addresses before AWS subnet reservations.

⭐ Key Point

The VPC CIDR defines the overall IP address range available inside your VPC.

2. CIDR Block

CIDR = Classless Inter-Domain Routing

It defines an IP address range. For example: 10.0.0.0/16

The VPC can then be divided into smaller ranges called subnets.

Example structure VPC 10.0.0.0/16 │ ├── Public Subnet │ └── 10.0.1.0/24 │ └── Private Subnet └── 10.0.2.0/24

A /24 contains 256 total IPv4 addresses, although AWS reserves 5 addresses in every subnet, so fewer are available for resources.

3. Creating Subnets

After creating the VPC, the next step is to create subnets.

A subnet is a smaller IP range inside the VPC.

Example

VPC: 10.0.0.0/16

Public subnet: 10.0.1.0/24

Private subnet: 10.0.2.0/24

These ranges are different and do not overlap.

4. Availability Zone

When creating a subnet, AWS asks you to select an Availability Zone (AZ).

Region └── Availability Zone A └── Public Subnet

You can also create another subnet in another AZ.

Recommended production architecture

Region │ ├── AZ-A │ ├── Public Subnet │ └── Private Subnet │ └── AZ-B ├── Public Subnet └── Private Subnet

This improves availability because your application does not depend on only one AZ.

⭐ Important A subnet belongs to exactly one Availability Zone.

5. Public and Private Subnets

Public Subnet

A public subnet is a subnet whose route table has a route to an Internet Gateway.

Typical resources:

  • Application Load Balancer
  • Public-facing EC2 instance
  • Bastion host

Private Subnet

A private subnet does not have a direct route to the Internet Gateway for internet access.

Typical resources:

  • Databases
  • Backend application servers
  • Private ECS tasks

Simple architecture

INTERNET │ ▼ Internet Gateway │ ▼ Public Subnet │ ┌──────┴──────┐ │ │ ALB EC2 │ ▼ Private Subnet │ Application/DB

6. Route Table

A Route Table contains rules that determine where network traffic should go.

Example

Destination Target
0.0.0.0/0 Internet Gateway

Meaning:

0.0.0.0/0 means: Any IPv4 destination that does not have a more specific route.

So: 0.0.0.0/0 → Internet Gateway provides a path from the associated subnet toward the internet.

7. Main / Default Route Table

When you create a VPC, AWS automatically creates some default networking components, including a main route table.

A subnet that isn't explicitly associated with another route table uses the VPC's main route table.

Important correction

A default/main route table does not automatically make a subnet public.

For a subnet to function as a public subnet, you generally need:

Subnet ↓ Route Table ↓ 0.0.0.0/0 → Internet Gateway

And the resource itself must have appropriate public addressing and security configuration.

8. Internet Gateway (IGW)

An Internet Gateway provides the VPC with a path for internet communication.

VPC │ └── Internet Gateway

After creating the Internet Gateway, you attach it to the VPC. Example: my-vpc → my-internet-gateway

9. Connecting a Public Subnet to the Internet

Creating an Internet Gateway alone isn't enough. You need to connect the pieces.

Step 1 — Create Internet Gateway (Internet Gateway)

Step 2 — Attach it to VPC (my-vpc → Internet Gateway)

Step 3 — Create a route table (my-route-table)

Step 4 — Associate the public subnet (my-route-table → Public Subnet)

Step 5 — Add internet route (Destination: 0.0.0.0/0 | Target: Internet Gateway)

Now the flow becomes:

Internet↕Internet Gateway↕Route Table↕Public Subnet

10. VPC Resource Map

AWS provides a Resource Map that makes the relationships easier to understand. Conceptually:

VPC │ ├── Public Subnet │ │ │ └── Route Table │ │ │ └── Internet Gateway │ └── Private Subnet │ └── Main/Private Route Table

This is extremely useful when learning AWS networking because you can visually understand how the components are connected.

11. Launching an EC2 Instance Inside Your VPC

After creating the VPC and subnets, you can launch an EC2 instance.

During EC2 creation: Network Settings → VPC

Instead of Default VPC, select my-vpc. Then select the required subnet.

For example:

  • VPC: my-vpc
  • Subnet: Private Subnet
  • Auto-assign Public IP: Disabled

12. Private EC2 Instance Example

Suppose your private subnet has: 10.0.2.0/24

You launch an EC2 instance into this subnet. AWS may assign it an address such as: 10.0.2.15

Private Subnet │ └── EC2 (10.0.2.15)

The important point is: The instance receives an IP from the subnet's CIDR range.

13. Complete VPC Architecture

The practical setup from this demonstration can be visualized as:

AWS REGION │ ▼ VPC 10.0.0.0/16 │ ┌──────────────┴──────────────┐ │ │ ▼ ▼ PUBLIC SUBNET PRIVATE SUBNET 10.0.1.0/24 10.0.2.0/24 │ │ ▼ ▼ Route Table Route Table │ │ ▼ │ Internet Gateway EC2 │ 10.0.2.x ▼ INTERNET

14. Public Subnet Traffic Flow

For a properly configured public resource:

User↓Internet↓Internet Gateway↓Route Table↓Public Subnet↓EC2 / ALB

The important configuration is: Public Subnet → Route Table → 0.0.0.0/0 → Internet Gateway

15. Private Subnet Traffic Flow

A private subnet normally does not have 0.0.0.0/0 → Internet Gateway directly.

If a private resource needs outbound internet access, a common architecture is:

Private EC2↓Route Table↓NAT Gateway↓Internet Gateway↓Internet

This allows the private resource to initiate outbound connections without making it directly reachable from the internet.

16. Important Difference: Public vs Private

Feature Public Subnet Private Subnet
Route to IGW Yes No direct internet route
Direct internet exposure Possible Not directly
Typical resources ALB, public web servers DB, backend servers
Public IP Can be used Usually not required
Outbound internet IGW NAT Gateway, if required

⚠️ Remember

A subnet is not public merely because it is called public-subnet. Its route table configuration determines whether it has a public route.

17. Important Concepts to Remember

  • VPC: Overall virtual network
  • Subnet: Smaller IP range inside VPC
  • Route Table: Decides where traffic goes
  • Internet Gateway: VPC ↔ Internet connectivity
  • NAT Gateway: Private Outbound Internet
  • EC2: Compute resource inside a subnet

⭐ Interview / Exam Questions

Q1. What is a VPC?
A VPC is an isolated virtual network in AWS where cloud resources can be deployed and networked.
Q2. What is CIDR?
CIDR defines the IP address range of a VPC or subnet. Example: 10.0.0.0/16
Q3. What is a subnet?
A subnet is a smaller IP range created inside a VPC.
Q4. What is a public subnet?
A subnet whose route table provides a route to an Internet Gateway.
Q5. What is a private subnet?
A subnet without a direct route to the Internet Gateway for internet access.

Q6. What does a route table do?
It determines where network traffic should be forwarded.
Q7. What is an Internet Gateway?
It provides a path between a VPC and the internet for appropriately configured public resources.
Q8. Why do we need an Internet Gateway?
To enable internet connectivity for resources that are configured for public access.
Q9. Can a private subnet access the internet?
Yes, for outbound access it can commonly use a NAT Gateway.
Q10. Where is an EC2 instance launched?
An EC2 instance is launched into a subnet, which is part of a VPC.

⚠️ Most Important Corrections

  • VPC is logically isolated, not necessarily a physically separate network.
  • An Availability Zone is not simply one physical server; it represents an isolated infrastructure location within a region.
  • Every subnet belongs to exactly one AZ.
  • EC2 is launched into a subnet, not directly into a VPC.
  • A default route table doesn't automatically make a subnet public.
  • Internet Gateway + route table + appropriate public addressing/security are needed for public connectivity.
  • NAT Gateway is for outbound connections initiated from private resources; it does not provide unsolicited inbound internet access.
  • A Security Group and NACL provide additional traffic controls around these networking components.
